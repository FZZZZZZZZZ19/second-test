# V1.50 屏幕菜单与调试

更新于2026-11-13。基于主干V1.3，未合入V1.4 IMU内环。

## 操作与菜单树

V1.50.4所有普通菜单使用五向上/下选择，中键点按确认；KEY1点按等同back返回上一级，主菜单无上一级则不操作。键盘页使用四向移动和中键确认，KEY1取消本页编辑并返回。KEY2无操作。统一消抖40ms，每次按下只执行一次，长按不重复，不再使用800ms长按确认。运行/图像页的KEY1返回仍会停止电机、暂停采集。

```text
main
├─ start → 当前灰度画面、启动提示、back
├─ para
│  ├─ vision → omega Kp / omega Kd / D filter s / camera calib / back
│  ├─ control → speed Kp(L+R) / speed Ki(L+R) / 单侧参数等 / back
│  ├─ hardware → 车身/轴距/轮距/左右轮径/轮端计数等 / back
│  ├─ save to flash
│  └─ back
└─ control
   ├─ run 30 → 实测速度、占空比、模式、stop / back
   ├─ image → 当前灰度画面 / back
   ├─ vofa → 未标定30%开环 / 标定后速度闭环、stop / back
   ├─ VOFA target m/s → 数字键盘 / back
   ├─ stop
   └─ back
```

各级都有back；KEY1与BACK返回时恢复上一级进入该页面的光标位置和对应分页，SAVE成功后也返回原参数项，新进入数字键盘仍从数字1开始选择。图像和电机调试页的back还会停止电机、关闭VOFA并暂停图像采集。control的back也停止。列表每屏五项，光标自动翻页；主菜单三项均为16×32大字，子菜单、数据和键盘字为8×16粗黑体风格点阵。黑白高对比，选中项反白，缓存减少重复刷屏。

V1.50.7数字键盘为独立4×4页面，上方显示参数名、旧值和当前输入，下方一次显示全部按键。五向键方向与屏幕位置对应，移动到边界停止；原空白格已改为SAVE，16格均可选。中键点按输入当前格，DEL删末位，CLR清空，负号-切换整段输入的正负，SAVE确认并持久保存当前输入，成功后返回，失败留在键盘提示且不改动RAM；BACK或KEY1取消并返回。空输入时SAVE保存当前内存参数；输入只有负号或只有小数点不能保存。旧值在上方显示，新输入从空白开始。拒绝空值、单独小数点、重复小数点、过长输入、非法数值或越界值。普通参数显示三位小数；相机系数显示五位有效数字的科学计数法，内部仍按float32存储。

```text
 1    2    3   DEL
 4    5    6   CLR
 7    8    9     -
 .    0   SAVE BACK
```

V1.50.3按用户实物安装方向修正：屏幕上=5、下=4、左=2、右=6、中=1，7表示无按键；相对上一版上下和左右分别对调。GPIO三位读取保持不变，仍是74HC148优先编码输入，不支持把同时按下多个方向解释成组合键。

键盘由160×80缩为120×72像素，左上角(4,52)，每格30×18，右下角止于(123,123)，不再把右侧功能列贴在屏幕最右缘。数字为7×14，DEL/CLR/BACK缩为6×12并居中留边；主菜单和其余页面字号不变。主机测试额外检查所有16格都在这个显示范围内，实际可视边界仍以板上屏幕反馈为准。

## start与stop

start恢复采集并进入图像页，自动请求READY，等待新会话有效视觉结果后请求START。继续检查相机、几何/编码器/方向标定、视觉验证开关等原有条件，最多等待2.5秒。失败显示start blocked，不强制驱动电机。默认标定零值仍禁止巡线。

stop在下一次5ms控制中断优先停止电机，清积分与规划状态；主循环暂停DVP采集/DMA和VOFA，屏幕与导航按键继续响应。这里只停止图像采集，传感器仍接电。故障时选择stop请求返回STATIC，再次启动仍需通过检查。中键确认和KEY1返回均为点按消抖触发，软件按键不能替代硬件断电。

## 参数、Flash和reset

| 菜单参数 | 源码参数 | 作用 |
|---|---|---|
| vision / omega Kp | lateral_kp | 横向偏差比例项，参与生成角速度 |
| vision / omega Kd | lateral_kd | 横向偏差变化率的微分项 |
| control / speed Kp(L+R) | kp_left、kp_right | 同时设置左右速度PI比例项 |
| control / speed Ki(L+R) | ki_left、ki_right | 同时设置左右速度PI积分项 |

电控页还支持单侧Kp/Ki、VOFA目标速度、正常速度、速度/占空比上限和左右前馈。再设置L+R项会覆盖两侧为同一值。增益输入范围0～10000；目标不能大于速度上限，降低速度上限不能低于现有各速度目标。

停止后修改，键盘不再提供仅写RAM的OK操作；SAVE或返回para确认save to flash才持久保存。看到saved to flash并返回参数列表才表示成功。保存前要求STATIC、PWM为零并保持500ms。未标定时原始计数不作为速度判断，不再因计数变化而禁止保存；反馈有效时仍要求计数不变、速度有限且绝对值小于0.01m/s。UI与物理存储共用maintenance.c检查，未修改发车标定检查。

保存期间暂停采集和TIM6，结束后重建时基、编码器基线和控制状态，再恢复TIM6，不自动发车、不自动重启。reset后按“默认值→实测宏→最新有效Flash”加载。全片擦除会清除保存值，普通reset不会。

使用原有双槽0x0803E000/0x0803F000，每条256字节，包含序号、CRC32、最后写入的提交标志。V1.50.6写schema=5，兼容schema=2/4；迁移时新增body_length_m/body_width_m为零（未知）。schema2缺失的debug_speed_mps置零，schema4已有的目标速度、增益、标定保持原值。不读取V1.4的schema=3。未测几何值可保持零并保存增益，但param_valid/param_can_arm仍拒绝缺失标定，不能因此发车。保存失败保留另一槽，掉电行为仍需实物验证。

Flash优先于编译时实测宏。如果先保存了未标定零值，后来再修改vehicle_calibration.h，须清除旧参数槽后再使用新的编译时标定，避免旧Flash覆盖新宏。

## run 30与VOFA

run 30直接让左右EN输出3000/10000，固定30%开环占空比，不经过速度PI，也不受正常比赛duty_limit默认25%的裁剪。可以不依赖相机和视觉标定。先架空确认方向。参数缺失时编码器速度可能显示零，应看enc有效标志；修改Kp/Ki不会影响run 30输出。

V1.50.5按当前需求：未标定时先保证PWM输出，确认vofa自动请求原run 30开环路径，左右均30%，不经过速度PI。目标速度参数可正常保存，但未标定开环不会追踪它。屏幕显示OPEN30 meas N/A、左右原始计数（每个5ms控制周期的delta）、PWM和set设定参考值。此时Kp/Ki不影响输出，也无法进行真实m/s速度闭环调参。若正在运行的闭环发生故障，不会自动切开环，仍按原逻辑故障回零。

真实几何、编码器、方向标定完成，参数合法、反馈有效且debug_speed_mps为正时，确认vofa才使用原速度闭环。其目标经过motion_plan加速限制后进入左右速度PI，输出继续受正常duty_limit限制。所有标定零值和掩码保持原值，不伪造标定通过。

协议依据[VOFA官方JustFloat文档](https://www.vofa.plus/docs/learning/dataengines/justfloat/)。UART3 PB10=TX、PB11=RX，115200、8N1、无流控。PB10接USB转TTL模块RX并共地，3.3V逻辑电平。电脑选择对应COM和JustFloat引擎。

每20ms发送一帧（50Hz），四通道单位m/s，顺序固定为：左要求速度、左编码器实测速度、右要求速度、右编码器实测速度。闭环时要求速度是送给PI的斜坡后目标；开环时I0/I2仅为保存的设定参考值。

闭环时四路为上述m/s数据；V1.50.8未标定开环时I0/I2发送保存的debug_speed_mps（例如0.200），I1/I3发送quiet NaN（常见小端字节00 00 C0 7F）。因此能画两条目标参考线，实测线暂不绘制。该参考值不参与开环控制，电机仍为固定30%占空比。闭环反馈无效时实测通道也发送NaN。每帧20字节：4个IEEE754 float32小端数共16字节，后接帧尾 `00 00 80 7F`。四路为1.0、0.5、-2.0、0.0时的示例：

```text
00 00 80 3F  00 00 00 3F  00 00 00 C0  00 00 00 00  00 00 80 7F
```

发送时不混入原有周期printf日志；退出实时页或stop后停止发送。本版不解析电脑发来的run/stop文本指令。

## V1.50.6硬件参数与返回位置

para顺序为vision、control、hardware、save to flash、back。hardware使用现有独立4×4键盘和SAVE流程，所有尺寸都按mm输入，内部转换为m后存入AppParam；每轮计数按整数输入。未测量的值仍为0，不自动写标定掩码。

| 屏幕项目 | 含义与字段 | 输入范围 |
|---|---|---|
| body length mm | 车身总长body_length_m，仅保存尺寸档案 | 0～3000mm |
| body width mm | 车身总宽body_width_m，仅保存尺寸档案，不是轮距 | 0～2000mm |
| wheelbase mm | 前后轮轴中心距离axle_m | 10～600mm |
| wheel track mm | 左右轮中心距离track_m | 30～600mm |
| eff track mm | 差速模型等效轮距effective_track_m；0沿用实际轮距 | 0或30～1500mm |
| L/R wheel dia mm | 左右有效轮径wheel_left_m/wheel_right_m | 10～300mm |
| L/R counts/rev | 左右车轮实际转一圈时累计计数counts_left/counts_right | 整数1～1000000 |
| cam offset mm | 现有相机前向偏置camera_forward_m，沿用原车体参考坐标定义 | 0～3000mm |

车长不替代轴距，车宽不替代轮距，车身尺寸目前不参与运动学。填写真实尺寸也不会自动确认方向和标定掩码；VOFA仍按已有条件决定开环或闭环。

返回举例：main的para→hardware→wheel track，KEY1返回时停在wheel track；再返回停在para里的hardware；再返回停在main里的para。VOFA返回停在control里的vofa，image返回停在image。列表跨页时也恢复相应页；KEY1与屏幕BACK行为一致，运动/图像页返回仍执行停止。

新字段追加到参数末尾，仍是256字节记录，52个float字段占208字节，加32字节头共240字节，不覆盖248处CRC与252处提交标记；编译期检查容量。主机覆盖mm↔m换算、计数整数/范围、旧schema2/4迁移、跨页光标、硬件页保存和所有返回路径。WCH构建及烧录校验通过。升级后实物RAM读回debug_speed_mps=0.20000000298，新增车身尺寸为0；进一步读取Flash两槽并验证CRC/提交标记，最新sequence=3、schema=4的原50个浮点字段与当前RAM逐字节一致，原保存值未丢失。硬件尺寸的实物测量及全项输入仍待用户后续完成。


## V1.50.7相机八参数标定页

入口：para → vision → camera calib。页面依次为ground_h0～ground_h7和back，使用已有五向上/下和中键选项。进入任一系数后用4×4键盘输入，原OK位置改为负号-；按一次加负号，再按一次去负号。CLR清空、DEL删末位，SAVE保存后返回同一系数，KEY1/BACK取消并返回，逐级光标和分页保持。其他非负参数仍拒绝负数。

这八项是原V1.3图像像素(u,v)到地面坐标(右向x、前向z，米)的映射系数，矩阵最后一项固定1：

```text
w = ground_h6*u + ground_h7*v + 1
x = (ground_h0*u + ground_h1*v + ground_h2) / w
z = (ground_h3*u + ground_h4*v + ground_h5) / w
```

系数按原数值输入，不按硬件页的mm换算。编辑范围为有限的-1000000～1000000；实际映射仍检查行列式、分母、前向距离和样本几何。逐项保存中间结果允许暂时为退化矩阵，此时视觉继续invalid；填写不会自动设置标定验证位。默认系数与现有实测值不被替换成示例值。

很小的系数显示为科学计数法，例如-0.000001显示old -1.0000e-06。键盘输入普通十进制小数，不提供e指数键，输入总长最多15字符（含负号与小数点），过长拒绝追加。显示的五位有效数字不改变内部float32保存值。

现有AppParam已经含这八项，参数格式仍为schema5，不新增字段或改变记录顺序。主机覆盖八项正负输入、符号切换、非法值、微小数显示、SAVE及取消返回；集成测试保存ground_h7=-0.000001并重新进入检查old显示。目标编译、烧录校验通过，实物全八项输入、实际标定矩阵正确性和巡线仍需后续验证。
