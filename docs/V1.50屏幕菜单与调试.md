# V1.50 屏幕菜单与调试

更新于2026-11-13。基于主干V1.3，未合入V1.4 IMU内环。

## 操作与菜单树

普通菜单只用KEY1。点按松手下移一格，到末尾循环；长按800ms确认，持续按住不重复，松手也不多移动。独立数字键盘页启用五向开关：上/下/左/右移动，中键点按确认；KEY1和KEY2在键盘页不执行操作。统一消抖40ms，每次按下只执行一次，长按中键不会重复输入。

```text
main
├─ start → 当前灰度画面、启动提示、back
├─ para
│  ├─ vision → omega Kp / omega Kd / D filter s / back
│  ├─ control → speed Kp(L+R) / speed Ki(L+R) / 单侧参数等 / back
│  ├─ save to flash
│  └─ back
└─ control
   ├─ run 30 → 实测速度、占空比、模式、stop / back
   ├─ image → 当前灰度画面 / back
   ├─ vofa → 自动速度闭环、目标/实测速度、stop / back
   ├─ VOFA target m/s → 数字键盘 / back
   ├─ stop
   └─ back
```

各级都有back；图像和电机调试页的back还会停止电机、关闭VOFA并暂停图像采集。control的back也停止。列表每屏五项，光标自动翻页；主菜单三项均为16×32大字，子菜单、数据和键盘字为8×16粗黑体风格点阵。黑白高对比，选中项反白，缓存减少重复刷屏。

V1.50.2数字键盘为独立4×4页面，上方显示参数名、旧值和当前输入，下方一次显示全部按键。五向键方向与屏幕位置对应，移动到边界停止；自动跳过空白格。中键点按输入当前格，DEL删末位，CLR清空，OK应用到RAM并返回参数列表，BACK取消并返回。旧值在上方显示，新输入从空白开始。拒绝空值、单独小数点、重复小数点、过长输入、非法数值或越界值。显示保留三位小数，内部按float32存储。

```text
 1    2    3   DEL
 4    5    6   CLR
 7    8    9    OK
 .    0       BACK
```

五向开关译码沿用原理图核对结果：上=4、下=5、左=6、右=2、中=1，7表示无按键。仍是74HC148优先编码输入，不支持把同时按下多个方向解释成组合键。

## start与stop

start恢复采集并进入图像页，自动请求READY，等待新会话有效视觉结果后请求START。继续检查相机、几何/编码器/方向标定、视觉验证开关等原有条件，最多等待2.5秒。失败显示start blocked，不强制驱动电机。默认标定零值仍禁止巡线。

stop在下一次5ms控制中断优先停止电机，清积分与规划状态；主循环暂停DVP采集/DMA和VOFA，屏幕与KEY1继续响应。这里只停止图像采集，传感器仍接电。故障时选择stop请求返回STATIC，再次启动仍需通过检查。单键长按确认需要800ms，不能把它当作瞬时硬件急停。

## 参数、Flash和reset

| 菜单参数 | 源码参数 | 作用 |
|---|---|---|
| vision / omega Kp | lateral_kp | 横向偏差比例项，参与生成角速度 |
| vision / omega Kd | lateral_kd | 横向偏差变化率的微分项 |
| control / speed Kp(L+R) | kp_left、kp_right | 同时设置左右速度PI比例项 |
| control / speed Ki(L+R) | ki_left、ki_right | 同时设置左右速度PI积分项 |

电控页还支持单侧Kp/Ki、VOFA目标速度、正常速度、速度/占空比上限和左右前馈。再设置L+R项会覆盖两侧为同一值。增益输入范围0～10000；目标不能大于速度上限，降低速度上限不能低于现有各速度目标。

停止后修改，ok只写RAM，返回para长按save to flash才持久保存。看到saved; survives reset才表示成功。保存前要求STATIC、PWM为零、编码器连续至少500ms无计数变化；反馈有效时还检查速度绝对值小于0.01m/s。

保存期间暂停采集和TIM6，结束后重建时基、编码器基线和控制状态，再恢复TIM6，不自动发车、不自动重启。reset后按“默认值→实测宏→最新有效Flash”加载。全片擦除会清除保存值，普通reset不会。

使用原有双槽0x0803E000/0x0803F000，每条256字节，包含序号、CRC32、最后写入的提交标志。V1.50写schema=4，兼容V1.3的schema=2；迁移时debug_speed_mps为零，需主动设置。不读取V1.4的schema=3。未测几何值可保持零并保存增益，但param_valid/param_can_arm仍拒绝缺失标定，不能因此发车。保存失败保留另一槽，掉电行为仍需实物验证。

Flash优先于编译时实测宏。如果先保存了未标定零值，后来再修改vehicle_calibration.h，须清除旧参数槽后再使用新的编译时标定，避免旧Flash覆盖新宏。

## run 30与VOFA

run 30直接让左右EN输出3000/10000，固定30%开环占空比，不经过速度PI，也不受正常比赛duty_limit默认25%的裁剪。可以不依赖相机和视觉标定。先架空确认方向。参数缺失时编码器速度可能显示零，应看enc有效标志；修改Kp/Ki不会影响run 30输出。

按本次确认，vofa采用速度闭环：先设置正的VOFA target m/s（debug_speed_mps），再确认vofa，自动启动两侧同速闭环，不启动run 30。需要几何、编码器、方向标定与有效反馈，不需要视觉标定。目标经过原motion_plan加速限制，再进入原速度PI；反馈无效、参数非法或控制节拍异常会故障回零。

协议依据[VOFA官方JustFloat文档](https://www.vofa.plus/docs/learning/dataengines/justfloat/)。UART3 PB10=TX、PB11=RX，115200、8N1、无流控。PB10接USB转TTL模块RX并共地，3.3V逻辑电平。电脑选择对应COM和JustFloat引擎。

每20ms发送一帧（50Hz），四通道单位m/s，顺序固定为：左要求速度、左编码器实测速度、右要求速度、右编码器实测速度。要求速度是送给PI的斜坡后目标。

每帧20字节：4个IEEE754 float32小端数共16字节，后接帧尾 `00 00 80 7F`。四路为1.0、0.5、-2.0、0.0时的示例：

```text
00 00 80 3F  00 00 00 3F  00 00 00 C0  00 00 00 00  00 00 80 7F
```

发送时不混入原有周期printf日志；退出实时页或stop后停止发送。本版不解析电脑发来的run/stop文本指令。

## 文件与验证

- menu_model.[ch]：纯菜单、KEY1事件、键盘、参数映射和JustFloat打包。
- menu_font.c/menu_font_data.h：粗无衬线字模与单字渲染，仅使用一个字形缓冲，不增加整屏帧缓冲；源字形来自DejaVu Sans Mono Bold，许可证见LICENSES/DejaVu-font.txt，可用tools/generate_menu_font.py和原TTF重新生成。
- debug_view.c：屏幕绘制、菜单动作、启动握手、Flash维护和UART3输出。
- camera_frame.c：暂停/恢复采集，停止后不再发布或重启帧。
- app_control.c：消费halt/run30/speed-debug请求。原比赛motion_plan、速度PI实现与元素状态机保持原实现。
- vehicle_param.c：schema4与schema2迁移，分别检查存储合法性和发车合法性。

主机七组配置通过，包括默认/配置路线回归、独立视觉/电控链接、菜单模型、实际UI加外设模拟、实际电控中断调试路径。键盘测试覆盖四向移动、边界、空格跳过、中键长按不重复、确认应用和取消返回。UI保存测试使用存储模拟，不代表物理Flash已验证。WCH GCC完整构建通过，Flash84584B、RAM31580B（含预留2KiB栈）；产物build/target/second-test-v1.50.hex。V1.50.2已完成目标板编程、校验和复位，真实五向键、Flash掉电、VOFA电脑串口联调、巡线、实际栈余量和ISR耗时仍待验证。
