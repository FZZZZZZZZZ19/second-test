# V1.50 屏幕菜单与调试

更新于2026-11-13。基于主干V1.3，未合入V1.4 IMU内环。

## 操作与菜单树

V1.50.4所有普通菜单使用五向上/下选择，中键点按确认；KEY1点按等同back返回上一级，主菜单无上一级则不操作。键盘页使用四向移动和中键确认，KEY1取消本页编辑并返回。KEY2无操作。统一消抖40ms，每次按下只执行一次，长按不重复，不再使用800ms长按确认。运行/图像页的KEY1返回仍会停止电机、暂停采集。

```text
main
├─ start → 当前灰度画面、启动提示、back
├─ para
│  ├─ vision → omega Kp / omega Kd / D filter s / back
│  ├─ control → speed Kp(L+R) / speed Ki(L+R) / 单侧参数等 / back
│  ├─ save to flash
│  └─ back
└─ control
   ├─ run 30 → 实测速度、占空比、模式、stop / back
   ├─ image → 当前灰度画面 / back
   ├─ vofa → 未标定30%开环 / 标定后速度闭环、stop / back
   ├─ VOFA target m/s → 数字键盘 / back
   ├─ stop
   └─ back
```

各级都有back；图像和电机调试页的back还会停止电机、关闭VOFA并暂停图像采集。control的back也停止。列表每屏五项，光标自动翻页；主菜单三项均为16×32大字，子菜单、数据和键盘字为8×16粗黑体风格点阵。黑白高对比，选中项反白，缓存减少重复刷屏。

V1.50.4数字键盘为独立4×4页面，上方显示参数名、旧值和当前输入，下方一次显示全部按键。五向键方向与屏幕位置对应，移动到边界停止；原空白格已改为SAVE，16格均可选。中键点按输入当前格，DEL删末位，CLR清空，OK应用到RAM并返回参数列表，SAVE确认并持久保存当前输入，成功后返回，失败留在键盘提示且不改动RAM；BACK或KEY1取消并返回。空输入时SAVE保存当前内存参数，OK仍要求有效输入。旧值在上方显示，新输入从空白开始。拒绝空值、单独小数点、重复小数点、过长输入、非法数值或越界值。显示保留三位小数，内部按float32存储。

```text
 1    2    3   DEL
 4    5    6   CLR
 7    8    9    OK
 .    0   SAVE BACK
```

V1.50.3按用户实物安装方向修正：屏幕上=5、下=4、左=2、右=6、中=1，7表示无按键；相对上一版上下和左右分别对调。GPIO三位读取保持不变，仍是74HC148优先编码输入，不支持把同时按下多个方向解释成组合键。

键盘由160×80缩为120×72像素，左上角(4,52)，每格30×18，右下角止于(123,123)，不再把右侧功能列贴在屏幕最右缘。数字为7×14，DEL/CLR/BACK缩为6×12并居中留边；主菜单和其余页面字号不变。主机测试额外检查所有16格都在这个显示范围内，实际可视边界仍以板上屏幕反馈为准。

## start与stop

start恢复采集并进入图像页，自动请求READY，等待新会话有效视觉结果后请求START。继续检查相机、几何/编码器/方向标定、视觉验证开关等原有条件，最多等待2.5秒。失败显示start blocked，不强制驱动电机。默认标定零值仍禁止巡线。

stop在下一次5ms控制中断优先停止电机，清积分与规划状态；主循环暂停DVP采集/DMA和VOFA，屏幕与导航按键继续响应。这里只停止图像采集，传感器仍接电。故障时选择stop请求返回STATIC，再次启动仍需通过检查。中键确认和KEY1返回均为点按消抖触发，软件按键不能替代硬件断电。

## 参数、Flash和reset

| 菜单参数 | 源码参数 | 作用 |
|---|---|---|
| vision / omega Kp | lateral_kp | 横向偏差比例项，参与生成角速度 |
| vision / omega Kd | lateral_kd | 横向偏差变化率的微分项 |
| control / speed Kp(L+R) | kp_left、kp_right | 同时设置左右速度PI比例项 |
| control / speed Ki(L+R) | ki_left、ki_right | 同时设置左右速度PI积分项 |

电控页还支持单侧Kp/Ki、VOFA目标速度、正常速度、速度/占空比上限和左右前馈。再设置L+R项会覆盖两侧为同一值。增益输入范围0～10000；目标不能大于速度上限，降低速度上限不能低于现有各速度目标。

停止后修改，OK只写RAM，键盘SAVE或返回para确认save to flash才持久保存。看到saved to flash并返回参数列表才表示成功。保存前要求STATIC、PWM为零并保持500ms。未标定时原始计数不作为速度判断，不再因计数变化而禁止保存；反馈有效时仍要求计数不变、速度有限且绝对值小于0.01m/s。UI与物理存储共用maintenance.c检查，未修改发车标定检查。

保存期间暂停采集和TIM6，结束后重建时基、编码器基线和控制状态，再恢复TIM6，不自动发车、不自动重启。reset后按“默认值→实测宏→最新有效Flash”加载。全片擦除会清除保存值，普通reset不会。

使用原有双槽0x0803E000/0x0803F000，每条256字节，包含序号、CRC32、最后写入的提交标志。V1.50写schema=4，兼容V1.3的schema=2；迁移时debug_speed_mps为零，需主动设置。不读取V1.4的schema=3。未测几何值可保持零并保存增益，但param_valid/param_can_arm仍拒绝缺失标定，不能因此发车。保存失败保留另一槽，掉电行为仍需实物验证。

Flash优先于编译时实测宏。如果先保存了未标定零值，后来再修改vehicle_calibration.h，须清除旧参数槽后再使用新的编译时标定，避免旧Flash覆盖新宏。

## run 30与VOFA

run 30直接让左右EN输出3000/10000，固定30%开环占空比，不经过速度PI，也不受正常比赛duty_limit默认25%的裁剪。可以不依赖相机和视觉标定。先架空确认方向。参数缺失时编码器速度可能显示零，应看enc有效标志；修改Kp/Ki不会影响run 30输出。

V1.50.5按当前需求：未标定时先保证PWM输出，确认vofa自动请求原run 30开环路径，左右均30%，不经过速度PI。目标速度参数可正常保存，但未标定开环不会追踪它。屏幕显示VOFA open30、左右原始计数（每个5ms控制周期的delta）、PWM和m/s N/A。此时Kp/Ki不影响输出，也无法进行真实m/s速度闭环调参。若正在运行的闭环发生故障，不会自动切开环，仍按原逻辑故障回零。

真实几何、编码器、方向标定完成，参数合法、反馈有效且debug_speed_mps为正时，确认vofa才使用原速度闭环。其目标经过motion_plan加速限制后进入左右速度PI，输出继续受正常duty_limit限制。所有标定零值和掩码保持原值，不伪造标定通过。

协议依据[VOFA官方JustFloat文档](https://www.vofa.plus/docs/learning/dataengines/justfloat/)。UART3 PB10=TX、PB11=RX，115200、8N1、无流控。PB10接USB转TTL模块RX并共地，3.3V逻辑电平。电脑选择对应COM和JustFloat引擎。

每20ms发送一帧（50Hz），四通道单位m/s，顺序固定为：左要求速度、左编码器实测速度、右要求速度、右编码器实测速度。要求速度是送给PI的斜坡后目标。

闭环时四路为上述m/s数据；未标定开环时四路均发送quiet NaN（常见小端字节00 00 C0 7F），不是零速度或编码器计数。曲线引擎可能不绘制这些无效采样。每帧20字节：4个IEEE754 float32小端数共16字节，后接帧尾 `00 00 80 7F`。四路为1.0、0.5、-2.0、0.0时的示例：

```text
00 00 80 3F  00 00 00 3F  00 00 00 C0  00 00 00 00  00 00 80 7F
```

发送时不混入原有周期printf日志；退出实时页或stop后停止发送。本版不解析电脑发来的run/stop文本指令。

## 文件与验证

- menu_model.[ch]：纯菜单、五向事件与KEY1返回、键盘、参数映射和JustFloat打包。
- menu_font.c/menu_font_data.h：粗无衬线字模与单字渲染，仅使用一个字形缓冲，不增加整屏帧缓冲；源字形来自DejaVu Sans Mono Bold，许可证见LICENSES/DejaVu-font.txt，可用tools/generate_menu_font.py和原TTF重新生成。
- debug_view.c：屏幕绘制、菜单动作、启动握手、Flash维护和UART3输出。
- camera_frame.c：暂停/恢复采集，停止后不再发布或重启帧。
- app_control.c：消费halt/run30/speed-debug请求。原比赛motion_plan、速度PI实现与元素状态机保持原实现。
- maintenance.c：UI与Flash存储共用的静态/零输出/有效测速检查。
- vehicle_param.c：schema4与schema2迁移，分别检查存储合法性和发车合法性。

主机七组配置通过，包括默认/配置路线回归、独立视觉/电控链接、菜单模型、实际UI加外设模拟、实际电控中断调试路径。键盘测试覆盖四向移动、边界、SAVE可选、中键长按不重复、所有页面KEY1返回、保存失败不改RAM、保存重载及保存后按住中键不重复写Flash。UI自动测试使用存储模拟；另已由用户在实物SAVE后确认old=0.200，并通过调试器reset run后读回debug_speed_mps=0.20000000298，验证正常保存及复位加载。写入中掉电未测。WCH GCC完整构建通过，Flash85084B、RAM31576B（含预留2KiB栈）；产物build/target/second-test-v1.50.hex。V1.50.5已完成目标板编程、校验和复位，VOFA电脑串口联调、巡线、实际栈余量和ISR耗时仍待验证。

## V1.50.5实物问题记录

调试器读到静态mode=1、两侧duty=0、右编码器delta=-6、测速valid=0；目标速度、轮径、每圈计数和标定掩码均为零。照片save: wait/check表示保存前置检查未通过，尚未写Flash。旧检查误把未标定原始计数活动当作已测得运动而持续阻止保存。现已分离存储与测速标定，并逐项提示SAVE: STOP FIRST / PWM NOT ZERO / WHEELS MOVE / BAD PARAM / WAIT 0.5S；真正写失败显示FLASH SAVE FAILED。新增默认标定零值且delta=-6的回归测试、开环NaN协议与VOFA请求开环测试。用户保存0.2和复位后读回均通过；实际PWM引脚波形仍待仪器验证。
