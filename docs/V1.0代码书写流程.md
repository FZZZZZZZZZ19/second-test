# V1.0 代码书写与验证流程

日期：2026-10-30。源码位于本仓库根目录，可直接看到 `User`、`Peripheral` 等文件夹。本文讲“从模板怎么写到当前版本”，实际函数和参数见[项目结构与主流程参数说明](V1.0项目结构与主流程参数说明.md)。

## 1. 先确定当前版本做到了什么

工程已经包含能编译链接的 CH32V307 固件：两侧编码器测速、两路 PH/EN 电机输出、侧速度 PI、差速运动规划、DVP 单帧所有权、白线候选路径、十字/Y/环岛状态机、两圈事件进度、参数双槽保存、本地按键和屏幕诊断。

默认配置处于静态调试：轮径、轮端计数等实测值为零，标定掩码为零，赛道事件序列为空。这些是明确的现场配置缺项，不是把未做功能返回“成功”。默认 HEX 不会因为上电或按启动键就让电机转动。

编译通过与主机回归已验证；烧录、实际运动、相机帧时序和比赛成绩尚未验证。正式赛道的元素顺序、环岛拓扑与终点距离必须实测填写。识别采用轻量规则，不能据此承诺任何路况都能识别。

## 2. 固定代码起点，保留已有底层

起点是 `FZZZZZZZZZ19/mode-for-ch32v307vct`，提交 `7673725bab177202212c43a409d778aab45c5fab`。

先保留时钟、启动汇编、WCH 外设库、逐飞设备库，再增加 `User` 应用文件。启动文件选择 `Startup/startup_ch32v30x_D8C.S`；另一份 D8 不参与构建。没有引入 RTOS，控制由 TIM6 固定节拍执行，图像处理在主循环执行。

预编译 `zf_device/libzf_device_config.a` 需要匹配 WCH 扩展指令和浮点 ABI，本版使用 `-march=rv32imafcxw -mabi=ilp32f`。不能拿普通 RISC-V 工具链的默认架构直接替代。

## 3. 先接硬件适配，暂时不给速度

第一步写 `board_config.h`，按两个 epro 的实际网络确定：PE9 左 EN，PE11 左 PH，PE14 右 EN，PE13 右 PH。详细链路见[引脚核对](hardware/引脚与驱动核对.md)。

第二步写 `board_port.c`，封装 GPIO/PWM、编码器原始计数、时钟、DVP 暂停重启和按键译码。上层不直接散写寄存器。EN 先当 GPIO 拉低，再切换 PWM；这样在应用初始化时保持刹车。电机初始化只调用一次。

第三步写 `motor.c`，集中完成 0～1 占空比到 0～10000 的转换、非有限数拒绝和零输出。普通循迹只允许向前，运行中不切换 PH，不通过让内轮反转来追线。

架空验证机械方向时，要在专门的低占空比测试中确认 `BOARD_*_PH_FORWARD`，确认后再恢复正式主流程。当前固件没有隐藏的串口强制转动命令，串口也不能绕过标定检查。

## 4. 写连续编码器采样，再考虑闭环

`side_encoder.c` 每 5ms 读取一次 TIM2/TIM4 的 16 位 CNT，不在每次采样后清零。`app_count_delta()` 做模 65536 的有符号差分，保证跨 65535→0 或反向跨零时仍连续。

该差分要求单个采样间隔内变化小于 32768 计数。正常速度下远小于这个值；调试时仍须检查实际编码器计数和中断是否被长时间阻塞。

手转轮子一圈，记录该侧编码器**轮端一整圈**的有效计数。不是只查电机轴的 PPR；主动齿轮、轮齿比和库计数模式都要一起计入。换算：

```text
本周期轮周距离 = π × 实测轮径 × 本周期有效计数 / 轮端一圈计数
侧速度 = 本周期轮周距离 / 实际采样时间
```

再做一阶滤波。滤波只平滑速度，里程累积使用本周期距离。轮胎滑移时，这个里程仍是轮周里程，不能声称它等于准确对地位置。

## 5. 写纯计算模块，让它们先在电脑测试

顺序是 `app_math` → `vehicle_param` → `speed_control` → `motion_plan`。

PI 输出的是 EN 占空比，比例项看当前速度误差，积分项补长期误差。输出饱和时，如果积分还想往饱和方向增加，就拒绝这次积分。输出下限为零，所以超速时能刹车减速，普通循迹不主动反转。

差速规划先限制车速变化，再限制转向：

```text
左侧速度 = v - ω × b / 2
右侧速度 = v + ω × b / 2
```

`b` 优先使用实测等效轮距，否则暂用几何轮距。两侧齿轮联动、四轮擦地使这个模型只是控制近似。限幅时成对处理左右目标，减少单边截断改变转弯趋势；停车时 v 和 ω 一起收敛到零。

主机测试调用的就是这些生产源码，不是另外抄一份算法。检查内容包括回绕、参数 CRC、PI 饱和、非有限值、两侧速度与加减速边界。

## 6. 把相机帧变成有明确所有权的数据

先写 `camera_frame.c`，然后才写识别。模板只有一块 188×120 灰度缓冲，不能在主循环扫描它时让 DMA 同时覆盖。

流程：采集 → 帧完成中断关闭 DVP 接收/DMA → 发布只读帧 → 主循环处理 → 归还帧 → 清接收状态并重新启用。重启后的第一帧丢弃，再持有下一帧。不是仅关中断后任由 DMA 继续写。

这个寄存器流程已经接入实际 DVP 中断，但完整帧、同步恢复、DMA 越界等仍须上板检查。`CAL_CAPTURE_VALIDATED` 和时序标定位默认不允许凭编译通过自动置位。

在静态模式按五向右键切到二值图，观察是否缺行、错行、闪断，以及白线能否稳定分开。显示使用借来的只读帧，显示完成后才归还。

## 7. 从连续白段构造路径，别把两支直接平均

`vision_line.c` 每隔 4 行扫描一次，总共 30 行，每行最多保留 4 个连续白段。宽度为 1 的孤立点不作为白线段。超出容量明确置 overflow，拒绝用截断数据发车。

从车身附近向远处逐行连接候选路径，按位置和趋势选连续分支。Y 分叉时复制路径候选，分别保留左右支。不能把左右支的中心平均成一条不存在的“中线”。

全白、全黑、缺少近端种子、白段过多都不会当作高可信路线。当前阈值为固定阈值，现场强反光和阴影需要调曝光、阈值及识别规则。

## 8. 写元素状态机，再接方向控制

十字：确认宽白带 → 保持前进路径通过 → 单线稳定 → 后轴清出再解除。规则要求直行。

Y：现场事件序列给出 Y 的身份 → 第一圈选左支 → 分支保持 → 汇合 → 后轴清出才记已通过 → 第二圈选右支。分支锁定保存几何位置与趋势，不依赖每帧候选数组编号永远一致。

环岛：按现场轮廓确定进入支 → 进入 → 内部跟随 → 满足最短距离并再次遇到经标定的出口特征 → 离开 → 后轴清出。V1.0 未启用 IMU，因此没有实际航向反馈；轮周距离加分叉重遇只是现场规则，需要实车验证，不能证明任意环岛都已绕满一周。

`track_profile.h` 的事件序列用于区分外观相似的 Y 和环岛。默认不配置，遇到无法分类的分叉请求停车。完整比赛模式还要求两圈每个 Y 的左右支记录均完成，并配置最后元素清出到终点的距离；没有假设细则一定提供特殊终点条纹。

## 9. 主循环给目标，5ms 中断管执行

主循环给出带 `frame_id`、`capture_ms`、`session_id` 的运动请求。中断检查它是否属于当前启动会话、是否仍新鲜，再运行运动规划和两侧 PI。

软超时默认 150ms：开始减速。硬超时默认 600ms：零 PWM 并进入 FAULT。旧帧不会因为被多次读取而重新变新。停止、重新准备都会重建会话或清空控制状态，避免上一轮运动请求突然作用到下一轮。

运行中不执行 Flash 擦写、不接收串口改参、不输出循环日志。Flash 保存只在静止的 STATIC 模式长按下键，先停定时器和采集，再写另一个槽，最后写提交标志，然后复位。

## 10. 在电脑上复现验证

从仓库根目录执行，Python 要求 3.9 或更新版本：

```powershell
python tools/test_host.py --cc C:/mingw64/bin/gcc.exe
python tools/build.py --toolchain "E:/RISC-V/MounRiver_Studio2/resources/app/resources/win32/components/WCH/Toolchain/RISC-V Embedded GCC/bin"
```

也可设置 `WCH_TOOLCHAIN` 环境变量。构建脚本每次完整编译源码，输出到 `build/target`，测试输出到 `build/host`。编译失败会非零退出，不会拿旧 HEX 充当新结果。

应用新增模块使用 `-Wall -Wextra -Werror`；原第三方库保留已存在的警告并记录。构建报告、固件和 SHA-256 保存在 `release/v1.0`。HEX/BIN 是默认禁止发车的配置，参数槽不会作为固件数据填入。

MounRiver 可导入根目录 `.project`，或打开 `.mrs/CH32V307VCT.mrs-workspace`。本次经过验证的是上述 CLI 构建；GUI 工程已排除 tests/tools/build/release，不把电脑测试 main 编进固件。GUI 编译结果需在所用 IDE 版本中另行核对。

## 11. 上板工作顺序

1. 电机架空，核对线束、供电和共地；首先确认上电 EN 为零。
2. 看 UART3 日志和屏幕，按右键看二值图；验证画面完整和左右关系。
3. 手转两侧轮子，读取正负计数；填轮端一圈计数、轮径、轮距、轴距。
4. 低占空比逐侧验证前进方向；再做低目标速度 PI 调试。先 P 后 I，逐步增加限幅。
5. 测相机行对应前向距离、相机到车体中心前移距离，验证帧暂停重启和 5ms 节拍，再填写标定位。
6. 先普通直线与弯道，之后十字，再 Y，再环岛。测有效轮距、通过距离、确认/释放时间。
7. 填现场事件序列和终点距离，逐圈检查每个 Y 的两支与环岛一周。最后才启用完整比赛模式。
8. 每次改变控制或识别代码，重新运行主机测试并重新生成目标固件；轮径、传动或场地变化后重新标定。

后续不要一开始就调高 `duty_limit` 和目标车速。先用数据确认路径、转向符号、测速与停车逻辑正确，再扩大工作范围。
