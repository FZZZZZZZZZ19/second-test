# 完整代码开发文档（当前V1.2）

2026-11-01。本文按已经提交的实现列模块边界、真实接口、调度和验证；旧版拟开发数据结构已从当前正文移除，历史版本保留在Git提交中。

## 1. 开发入口与模块边界

模板起点为mode-for-ch32v307vct@7673725。当前User已分vision/control/board/integration/shared/config。源码清单、主流程和完整参数见[项目结构说明](项目结构与主流程参数说明.md)，按步骤实现与上板见[代码书写流程](代码书写流程.md)。

视觉入口vision_pipeline_step只给VisionOutput，control_path_step只消费该协议并生成MotionRequest。集成app_main_poll连接两者；控制中断运行差速、测速PI和PWM。算法替换原则见[分层与调参](V1.2视觉电控分层与调参.md)。

## 3. 代码连接与异常传播

app_boot加载默认参数、CAL和Flash，启动TIM6及相机；app_main_poll有新帧才运行视觉，给电控后发布请求。会话改变清历史；控制拒绝重复帧、错会话、NaN/无穷及非法距离/速度。

VisionOutput无效时仍保留stop_requested；control_path_step会复制停车请求，即使不生成有效角速度。控制中断执行旧有效请求的年龄检查，不会因反复读同一帧而刷新拍摄时间。图像软超时先减速，硬超时进入FAULT。

边界容量、种子栈和路径数组有上限，溢出拒绝有效视觉目标。DVP缓冲借用期暂停DMA，不依赖volatile保证整帧安全。消息结构复制使用短临界区，运行中不写Flash。

## 4. 参数持久化和硬件绑定

AppParam浮点字段表定义明确序列化顺序；vision/control调参头分别写默认值，param_defaults统一初始化，校验后可编码。256字节记录含版本、序号、CRC与最后写入的提交标记，Flash双槽保留上一条有效记录。修改结构或格式须升级/兼容参数格式，不能直接memcpy结构作为持久化协议。

引脚见[硬件核对](hardware/引脚与驱动核对.md)。board目录封装GPIO/PWM/计数器/DVP/时基；识别算法不直接使用外设寄存器。没有电流闭环、未启用IMU和硬件看门狗，实际方向和帧时序须上板验证。

## 5. 验证与交付

运行tools/test_host.py：完整默认/测试路线回归，以及只链接视觉和只链接电控的两套测试。运行tools/build.py：递归收集User，WCH GCC8.2完整构建，输出当前版本ELF/HEX/BIN/MAP、编译记录和源文件/固件SHA-256。
