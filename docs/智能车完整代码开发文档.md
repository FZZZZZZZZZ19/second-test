# 完整代码开发文档（当前V1.2）

2026-11-01。本文按已经提交的实现列模块边界、真实接口、调度和验证；旧版拟开发数据结构已从当前正文移除，历史版本保留在Git提交中。

## 1. 开发入口与模块边界

模板起点为mode-for-ch32v307vct@7673725。当前User已分vision/control/board/integration/shared/config。源码清单、主流程和完整参数见[项目结构说明](项目结构与主流程参数说明.md)，按步骤实现与上板见[代码书写流程](代码书写流程.md)。

视觉入口vision_pipeline_step只给VisionOutput，control_path_step只消费该协议并生成MotionRequest。集成app_main_poll连接两者；控制中断运行差速、测速PI和PWM。算法替换原则见[分层与调参](V1.2视觉电控分层与调参.md)。

## 2. 写代码时先盯住三个入口

| 入口 | 传入什么 | 得到什么 | 它为什么需要存在 |
|---|---|---|---|
| vision_pipeline_step | 一帧图、只读参数、进度和当前会话 | VisionOutput，以及供显示的诊断特征 | 集中完成看路与选路，换视觉算法时保留外部协议 |
| control_path_step | VisionOutput、方向PD历史和参数 | MotionRequest | 把视觉方向变成电控角速度，图像算法不用懂电机 |
| app_control_tick_isr | 不从参数列表传入，读取当前消息和硬件反馈 | 更新左右PWM和控制快照 | 每5ms稳定执行测速、限制与速度闭环 |

`VisionOutput`像视觉给电控的一张小纸条：写目标方向、像素距离、是否可信、是否停车，还写照片时间和本次运行身份。`MotionRequest`则是电控算好的运动要求，多了车体角速度omega。两者不是同一个东西。

### 按一次主循环跟读源码

1. 打开 `User/integration/app_boot.c` 找 `app_main_poll`，先看它如何借到完整一帧。
2. 进入 `User/vision/vision_pipeline.c`：画面变成候选路径，元素状态选支，目标几何写入VisionOutput。
3. 回到集成入口，再进入 `User/control/path_control.c`：检查纸条的身份和数值，用方向PD生成MotionRequest。
4. 集成入口把请求放入消息交换区，显示后归还帧。这一轮主循环结束。
5. 打开 `User/control/app_control.c`，跟随每5ms中断：取运动请求，读编码器，计算左右目标，两套PI更新PWM。

不要把上面顺序理解成“主循环等待中断做完”。两者分别运行，交换的是完整消息；中断发生时可以临时打断主循环。

### 替换其中一个算法的实际步骤

换视觉：先让新视觉函数生成合规VisionOutput，再运行视觉独立测试，最后连接现有电控。换方向算法：保留control_path_step入口和MotionRequest输出，用人工构造的视觉消息先测符号、非法值和停车，再接真实图像。

替换后，除了正常场景，还检查黑图、重复帧、旧会话、NaN和stop_requested。否则“能转弯”的新算法可能把原有停车保护弄丢。

真实声明放在本文末尾，供写调用时核对参数顺序，不要求先逐行阅读头文件。

## 3. 代码连接与异常传播

app_boot加载默认参数、CAL和Flash，启动TIM6及相机；app_main_poll有新帧才运行视觉，给电控后发布请求。会话改变清历史；控制拒绝重复帧、错会话、NaN/无穷及非法距离/速度。

VisionOutput无效时仍保留stop_requested；control_path_step会复制停车请求，即使不生成有效角速度。控制中断执行旧有效请求的年龄检查，不会因反复读同一帧而刷新拍摄时间。图像软超时先减速，硬超时进入FAULT。

边界容量、种子栈和路径数组有上限，溢出拒绝有效视觉目标。DVP缓冲借用期暂停DMA，不依赖volatile保证整帧安全。消息结构复制使用短临界区，运行中不写Flash。

## 4. 参数持久化和硬件绑定

AppParam浮点字段表定义明确序列化顺序；vision/control调参头分别写默认值，param_defaults统一初始化，校验后可编码。256字节记录含版本、序号、CRC与最后写入的提交标记，Flash双槽保留上一条有效记录。修改结构或格式须升级/兼容参数格式，不能直接memcpy结构作为持久化协议。

引脚见[硬件核对](hardware/引脚与驱动核对.md)。board目录封装GPIO/PWM/计数器/DVP/时基；识别算法不直接使用外设寄存器。没有电流闭环、未启用IMU和硬件看门狗，实际方向和帧时序须上板验证。

## 5. 验证与交付

运行tools/test_host.py：完整默认/测试路线回归，以及只链接视觉和只链接电控的两套测试。运行tools/build.py：递归收集User，WCH GCC8.2完整构建，输出当前版本ELF/HEX/BIN/MAP、编译记录和源文件/固件SHA-256。

本版记录位于release/v1.2。文档更新不重写已发布固件报告；代码更改需重新测试/构建。旧版内容和固件的固定入口见[版本记录](版本记录.md)。
