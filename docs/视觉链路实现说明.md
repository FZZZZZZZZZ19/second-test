# V1.6 视觉与电控联调

`control → image` 可先查看摄像头画面。采集与视觉输入都是 188 列 × 120 行的灰度图，屏幕显示中间 128 列。进入主循环的是采集模块提供的稳定帧，视觉通过行距读取原始灰度，预览显示原始画面。

## 一帧图如何变成电机指令

1. `app_main_poll` 获取 `FrameView`，其中含原图、行距、帧号和拍摄时间。
2. `team_vision_points` 用大津阈值二值化，找底部白线，从左右边界巡边。逐行统计白段，识别元素并补线，再选近、中、远三个像素点。
3. `team_vision_step` 使用当前 `AppParam.ground_h0…h7` 投影，填入 `VisionOutput`。三个地面点的前向坐标统一减 35.5 mm (0.0355 m)。近点给出横向偏差，近点指向中点的连线给出地面方向。转向前馈使用近点、近段补采点和中点计算曲率，补采点几何不足时曲率置零。屏幕继续标记原有近、中、远三点。直道、直角弯和其他元素分别使用普通、弯道和元素速度参数。
4. `control_path_step` 以 `omega = -v × curvature - heading_gain × heading_rad - Kp × lateral_m - Kd × d(lateral_m)/dt` 计算左转为正的角速度。近段已经转向时，方向项在近点仍居中的情况下也能给出转向。随后 5 ms 控制中断运行运动规划和左右轮速度 PI，产生 PWM。

| 字段 | 电控使用方式 |
|---|---|
| `lateral_m` | 近点横向偏差，右正。用于方向 PD |
| `forward_m` | 近点前向坐标，单位米。减 35.5 mm (0.0355 m) 后允许为负，原始投影仍须在相机标定原点前方 |
| `curvature` | 地面路径曲率，右弯正，单位 1/m。用于前馈 |
| `heading_rad` | 近点指向中点的地面方向，相对车头正前方，向右为正。单位 rad |
| `speed_cap_mps` | 当前元素建议速度，运动规划还检查速度与加速度上限 |
| `frame_id / capture_ms / session_id` | 检查重复帧、帧龄及当前运行会话 |
| `state / confidence / valid` | 说明所处阶段和本帧是否可用。有效输出的 60 是固定门槛值 |
| `element_debug` | 原始视觉 `state`、`flag` 和可用标志，供短跑预览显示 |
| `reset_derivative / stop_requested` | 路段切换或丢线恢复清方向微分。队友链路暂未生成终点停车请求 |

画面全同灰度、找不到起点、巡边超限、补线失败、无效投影或前向点序不成立时，该帧标为无效。电控按既有帧龄机制处理上一条有效请求，达到软超时后减速，达到硬超时后故障停车。

## 联调范围

- 原来队友代码未被主循环调用，还要求调用者定义阈值变量、逐帧填图，并把投影系数写死。本次在接口层补齐这些依赖，从板上当前标定统一投影。
- 二值图按位存储，每侧巡边最多 512 个点。点数到顶且巡边尚未结束时返回无效，避免越过数组。该取舍需要用长轮廓和复杂元素的实拍帧验证。
- 当前 `LR=0`，Y 和环岛按队友左侧策略运行。右环岛、路线指令、圈数和终点停车仍待接入或验证，正式路线 `CAL_FULL_RACE` 保持禁止发车。普通 `start` 仍受原有的标定、相机与时序确认条件限制。
- 联调测试使用合成画面检查右偏给右转、标定改动生效、无效画面拒绝和有填充行距的读取。接下来用原图回放或架空实测逐项核验十字、分叉、左环岛、右环岛和处理耗时，再进行低速巡线。

目标构建使用 Flash 87,644 B、RAM 62,444 B（含 2 KiB 预留栈），RAM 剩余 2,068 B。十组主机测试通过。上板仍需测量复杂画面耗时、丢帧和栈余量。

## 用小弯道调转向

1. 在地板铺与赛道同样明暗的线，先留一小段直线，再接平缓弯道。将车摆在直线起点，先用 `control → image` 确认摄像头能看到车前的近点和弯道。
2. 停车后进入 `para → vision`。用 `turn preview px` 调前瞻距离，默认 65，可设 35～90 的整数。从原图底部附近的参考点量距离，数值改变中、远点以及计算近段曲率用的补采点，近点仍由车前巡边入口决定。数值调小通常晚转，调大通常早转。实际提前多少取决于车速、相机安装和弯道形状。用 `heading gain` 调近段方向的转向强度，默认 2.0 s⁻¹，可设 0～20。设 0 可关闭方向项，曲率前馈和 `omega Kp / omega Kd` 仍参与转向。两个参数按 SAVE 后复位也会保留。
3. 进入 `control → track tune`。等待新会话的有效画面时显示 `wait for track`。起步后顶部显示剩余时间和限速后的目标速度，底部显示该预览帧的原始分类 `state` 和元素阶段 `flag`。例如 `state:4 flag:11` 表示环岛阶段 11，`state:- flag:-` 表示该帧没有分类结果。原始 `state` 的 0～4 依次为普通、弯道、分叉、十字、环岛。
4. 红色十字标记当前帧的近、中、远点，超出裁切范围的点直接略过。预览每 100 ms 最多刷一张，结束后保留最后一帧及其状态。到时自动停车并显示 `tune done`。可随时按确认键或 KEY1 停车并返回。等待画面超过 2 秒、有效帧太旧、丢线或测速失效也会停车。

短跑模式只依赖相机、实装轮速参数、有效测速和本次三点投影，不要求正式比赛路线确认。正式 `start` 的校验独立保留。`para → control` 集中调整速度，SAVE 写入 Flash：

| 菜单项 | 用途 |
|---|---|
| `speed limit m/s` | 全局速度上限，运动规划执行 |
| `normal speed m/s` | 普通路段的目标速度 |
| `corner m/s` | 直角弯的目标速度 |
| `element m/s` | 十字、分叉和环岛的目标速度 |
| `tune speed m/s` | 短跑的独立目标，默认 1 m/s |
| `tune time s` | 短跑时长，默认 10 秒，可设 0.5 至 30 秒 |
| `accel m/s2` | VOFA、短跑和赛道的提速斜率，默认 0.3，菜单可设 0.01～5.0 m/s² |
| `VOFA target m/s` | VOFA 轮速闭环的独立目标 |

目标可先保存，运行时自动按全局限速裁剪。设置范围最高 5 m/s。Flash 格式 15 保存前瞻距离，读取旧记录时这一项默认 65 px。已有的方向增益和其他参数继续读取。

## 切换轮速反馈滤波

停车后在主菜单进入 `control → speed LPF ON/OFF`，按确认键切换并保存。有 `saved` 提示表示写入 Flash 成功。旧参数默认 ON，沿用原本的一阶低通，时间常数默认 25 ms。OFF 时左右 PI 和 VOFA 使用当次 5 ms 编码器速度估计，ON 时使用各自滤波后的速度。原始超速判定仍在滤波前执行。

## 实际代码变化

`User/vision/vision_boundary.c` 新增 Otsu 自动阈值、底部附近种子搜索、连通域提取、边界追踪、画面截断区间和折点记录。`User/vision/vision_line.c` 使用同一个连通域生成候选路径，`User/vision/vision_target.c` 使用选中出口/折点给方向与距离，`User/control/path_control.c` 只做曲率前馈＋横向偏差PD，`User/integration/debug_view.c` 使用当前帧 Otsu 阈值显示二值图。

处理链路：灰度帧 → 全帧256级直方图/Otsu → 底部最近白色道路连通域 → Moore八邻域边界追踪 → 截断区间及折点 → 连续候选路径 → 原有多帧元素状态机 → 米制偏差/前向距离/曲率 → 差速约束与侧速度PI。

摄像头与队友视觉接口使用 `image[120][188]`，即120行、188列的灰度图。列号 `u=0..187`，行号 `v=0..119`，视觉直接用整帧坐标和原始八参计算地面位置。屏幕宽128像素，预览显示原图第30～157列。 DVP连续采集，视觉借用完整稳定快照，处理结束后归还。连通域位图占2820字节。

## 截断与折点的具体定义

截断是**所选道路连通域与画面周边相交的连续白区间**，不是白黑转换的像素点数。周边按下→左→上→右循环遍历，角点只出现一次，跨起始点的区间也只记一次。宽度小于2像素忽略。最多8个区间，超容量拒绝作为有效帧。

从画面底部向上最多9行寻找离中心最近的白像素，再做四连通扫描线扩展。因此独立平行白线不会混入本车道路；如果道路被遮挡而断开，远端不会被凭空连接。种子栈最多128项，溢出拒绝帧。

边界追踪采用八邻域 Moore 邻域搜索；以“起点和首条边再次出现”判定闭合，不只看回到一个像素。最多遍历两倍图像像素数，不能闭合则拒绝帧。每8步用前后方向变化提取折点，最多保留16个，保留位置和画面左右半区标记。

当前追踪所选连通域的一条外轮廓，行扫描继续保留多白段用于分支选择；**尚未逐一枚举环岛内部所有封闭孔洞轮廓**。折点的左右标签表示画面半区，不等于严格意义的“车道左边界/右边界身份”。这是当前实现与截图文字中理想边界模型的区别，不能将其当成已经完成通用拓扑重建。

## 元素判据与控制

| 证据 | 当前处理 |
|---|---|
| 两个截断区间 | 普通道路候选；没有足够有效路径仍拒绝 |
| 两个区间、存在近处折点 | 普通弯道选目标时参考选中侧折点 |
| 四个区间且覆盖下/左/上/右四边 | 十字候选，目标强制选上边出口，接原确认/通过/清出状态 |
| 三个区间 | 分叉候选，接原选支和两圈记录 |
| 四个区间且至少三个中点位于同一画面半区 | 环岛候选，结合现场路线身份接原环岛状态机 |
| 低对比度、无法闭合、容量溢出 | 不发布有效运动目标，继续由原超时策略停车 |

截断个数只是候选证据，十字和分叉仍用确认时间及通过状态；Y/环岛仍依赖经验证的现场事件顺序区分。环岛没有改成“第二次四截断就直接出环”，保留进入、内部跟随、最短进度、出口重遇、清出状态。现有未配置路线遇到分叉会停车。

对于没有上边出口的90°弯，候选路径可以选择左/右边出口，方向不再仅由远端行中线的平均数决定。连通路径在至少3个采样行有效且有两个出口时允许最低60的置信度，以适应只在近处可见的直角弯。

## 控制接口

视觉在 `User/shared/vision_control.h::VisionOutput` 输出下列字段，再由control生成MotionRequest：

- `lateral_m`：最近有效采样点在车体坐标系中的横向偏差，右正，米。
- `forward_m`：同一点前向距离，米，必须大于零。
- `curvature`：选中路径近、中、远三点的有符号外接圆曲率，右弯正，1/m。

使用实测 ground_h0..h7 矩阵转换坐标。缺失、奇异矩阵、非法投影、前向顺序不成立或不足三点均 invalid。不会用出口像素角兜底。原接口字段 direction_rad/distance_px 仅保留结构兼容，生产端置零，电控不读取。元素状态机仍选择 path_index；当前几何估计只使用该分支的采样行，不使用出口与折点平均策略。直角、遮挡和路径非单值时需要现场验证。

## 标定、资源与验证

`CAL_VISION_V2_VALIDATED` 默认0。它与原标定条件一起决定是否允许准备，旧Flash记录不能绕过这个编译期检查。确认完整帧、图像朝向、元素选择、方向增益、最坏处理时间后才手动置1。硬件尺寸及机械方向等原标定仍必需。

主机测试直接调用生产代码，包含亮度改变后的直角弯、十字对面目标、三出口分叉、无关平行线过滤、相连白段超容量、低动态范围及原有控制/参数/状态回归。主机案例不代表真实镜头畸变、反光、运动模糊和环岛拓扑已经验证。

构建方法同README，当前工具链位置为MounRiver Studio3。新版固件和源文件校验记录保存在 `release/v1.2`；旧 `release/v1.0` 保留为历史快照。当前32KiB RAM配置接近容量上限，已预留2KiB栈，但运行栈峰值和处理延迟仍需要实物测量。
