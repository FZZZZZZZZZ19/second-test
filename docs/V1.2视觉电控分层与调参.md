# V1.2 视觉与电控分层、替换和调参

日期：2026-11-01。本版将视觉处理和电控算法分目录，并将原先混在方向控制函数中的目标点几何与方向PD拆成两个独立模块。

## 目录和职责

```text
User/
  vision/                 只做看路、识别、选支和目标几何
    vision_api.h          视觉公开入口
    vision_pipeline.c     一帧处理入口
    vision_boundary.c     Otsu、连通域、外轮廓和截断
    vision_line.c         候选路径
    track_element.c       十字、分叉、环岛、两圈进度
    vehicle_progress.c    根据反馈判断后轴清出
    vision_target.c       目标点→方向角与像素距离
  control/                把目标变成实际运动
    control_api.h         纯控制公开入口
    path_control.c        方向PD
    motion_plan.c         差速与加减速约束
    speed_control.c       两侧速度PI
    side_encoder.c        测速
    motor.c               占空比输出
    run_manager.c         启停状态
    app_control.c         5ms执行、安全检查、反馈
  board/                  引脚、PWM/计数器、DVP帧与时间基准
  integration/            初始化、模块连接、消息交换、显示、参数存取
  shared/                 共享数据类型、数学和参数序列化
    vision_control.h      VisionOutput，两条链路的连接协议
  config/
    vision_tuning.h       视觉识别、几何与元素默认参数
    control_tuning.h      方向PD、轮速PI、速度与限幅默认参数
    vehicle_calibration.h 实车尺寸/计数/图像时序标定
    track_profile.h       现场路线顺序
  main.c                  入口；厂商系统和中断文件仍保留在User根目录
```

## 两条链路如何连接

集成入口是 `integration/app_boot.c::app_main_poll`：

```text
camera_frame_acquire
  → vision_pipeline_step(..., &observation)
  → control_path_step(..., &observation, ..., &request)
  → app_exchange_publish_motion(&request)
  → 5ms控制中断读取请求、规划两侧轮速、运行PI并写PWM
camera_frame_release
```

`vision_pipeline_step` 不调用电控实现；它输出 `VisionOutput`。`control_path_step` 不读取图像、轮廓、白段或相机寄存器，只消费这个输出。调度仍是主循环做图像与方向PD，中断做固定节拍速度控制，拆目录没有把整帧处理移进中断。

## VisionOutput 协议

| 字段 | 含义 |
|---|---|
| `direction_rad` | 图像目标方向，右为正，单位rad；不是车辆真实转角 |
| `distance_px` | 图像参考点到目标的像素距离；不是米，当前未用于距离减速 |
| `speed_cap_mps` | 选路侧建议的最高车速，电控仍施加自身限幅 |
| `state` | 当前道路元素状态，供记录与控制衔接 |
| `confidence`, `valid` | 可信度与有效性 |
| `stop_requested` | 元素判断请求停车；即使观察无效也要传递 |
| `reset_derivative` | 目标/元素切换时，通知电控清方向D历史 |
| `frame_id`, `capture_ms`, `session_id` | 帧身份、拍摄时间与启动会话；不能省掉 |

电控拒绝重复帧、错误会话、NaN/无穷、非正距离和负速度。画面右目标经方向PD转换为负车体角速度，再形成左快右慢的侧速度。视觉不再输出 `omega_raw`，这个量由电控计算。

共享头目前通过 `app_types.h` 取得公共类型，参数持久化仍用扁平 `AppParam` 格式，保持既有CRC与记录布局。目录拆开不等于把整车物理参数复制两份：几何与只读进度反馈仍由双方共享。

## 替换视觉算法

保留 `vision_api.h` 中 `vision_pipeline_step` 的对外签名与 `VisionOutput` 协议。可以替换Otsu、边界搜索、候选路径或整个帧处理实现；入口负责返回有效性、身份与时间戳，以及方向和像素距离。电控源文件不用读取新视觉算法的私有特征。

`VisionFeatures` 是当前算法的诊断数据出口，供静态图像显示；替换整套算法时可以由适配层清零或填入兼容诊断内容。它不作为电控算法的输入。摄像头采集在 `board`，通常不随识别方法改变。

## 替换控制算法

方向算法从 `control_path_step` 进入，可以将PD换成其他方法，仍输出 `MotionRequest`。左右轮运动约束在 `motion_plan_step`，速度闭环在 `speed_pi_step`；可以分别替换，不必改Otsu、追踪或元素识别。

保留无效输入、超时、会话隔离和停止请求的处理。新算法仍应遵守普通循迹两侧不反转、限速、加减速等已有约束。

## 调参应该改哪个文件

`config/vision_tuning.h`：图像中心、近远线宽、行间跳变、元素确认/释放时间、清出余量、环岛最小进度等。

`config/control_tuning.h`：方向P/D及D滤波、编码器滤波、两侧速度P/I及前馈、目标速度、最高侧速度、占空比、加减速和图像超时。

字段名 `visual_kp/kd/tau` 为兼容旧参数记录保留，职责是电控的方向控制器，因此归入control调参文件。`speed_normal/corner/element` 也在control文件里设默认值，视觉根据路况选用它们作为建议上限。

实测尺寸、轮端计数等仍填 `vehicle_calibration.h`，现场元素顺序填 `track_profile.h`。旧 `threshold` 只为参数格式兼容保留；当前Otsu不使用固定阈值。

Flash有效记录仍优先覆盖编译默认值。改变默认参数后先处理旧参数槽，再烧录，否则可能继续读旧值。本版没有增加在线串口改参；发车后仍冻结配置。

## 独立测试和构建

执行 `python tools/test_host.py --cc C:/mingw64/bin/gcc.exe` 会运行四项：

1. 原完整回归，默认路线配置。
2. 原完整回归，测试用路线配置。
3. `test_vision_module.c`：只链接视觉和共享数学，用合成图像验证输出；不链接控制或硬件对象。
4. `test_control_module.c`：只链接控制和共享参数/数学，用手工构造的VisionOutput验证转向、重复帧、会话、非法数值和停车传播；不链接视觉或硬件对象。

目标构建脚本已递归扫描User子目录，MounRiver工程已加入全部新头文件目录。版本升级V1.2，产物在 `release/v1.2`。旧V1.0/V1.1目录保留为历史快照。

上板与赛道验证状态不因分层而自动改变，仍需完成实车方向、视觉时序和参数标定。
