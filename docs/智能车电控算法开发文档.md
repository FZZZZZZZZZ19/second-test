## 0. 先把车、赛道和规则说清楚

### 0.1 本文适用什么车

“二轮考核”指第二轮考核。细则第2页提供了两张参考车模照片；从照片可以进一步确定结构，不能再把车轮布局当成完全未知。

**图片直接可见：**四个轮子，左右各两个；侧面前后轮均有大齿轮；两轮之间的小齿轮同时与两个大齿轮啮合；摄像头装在高支架上；控制板和屏幕在上层。可见部分没有转向舵机或转向拉杆。

**结合图片和双路电机驱动板的结构判断：**该参考车应为左右两侧分别驱动的四轮差速车，同侧前后轮由齿轮关联，转弯时通过两侧速度差产生偏航，并伴随轮胎横向擦地。这属于四轮差速滑移转向模型。背面未完全展示，电机与每侧传动的对应关系仍需实物确认。

本文据此采用四轮差速滑移转向作为参考车的开发模型。若你购买的是细则中的同款车，可直接按这个开发顺序推进；电机标号、齿轮齿数、轮径、轮距、前后轮轴距仍需测量。

### 0.1.1 四个轮子如何被两路电机控制

按照片所示传动，示意如下；不表示精确尺寸和电机实际位置：

```text
                 摄像头观察方向 / 车前方
                         ↑
       左前轮 ○                         ○ 右前轮
              ╲ 同侧齿轮传动   同侧齿轮传动 ╱
          左侧电机/小齿轮       右侧电机/小齿轮
              ╱                         ╲
       左后轮 ○                         ○ 右后轮

       左路PH/EN控制这一侧      右路PH/EN控制这一侧
```

同一个小齿轮直接啮合两个大齿轮时，两只大齿轮都与小齿轮反向，因而同侧两只轮子彼此同向。若两只大齿轮齿数和轮胎有效直径相同，同侧前后轮理论圆周速度相同。

因此程序首先控制两条“侧速度”：左侧速度、右侧速度。只有两套电机输出、两套侧速度闭环；前后四个轮子的运动由两侧机械传动关联，无法分别下发四个独立轮速。

若前后轮有效直径不同，它们即使角速度相同，圆周速度也不同，会互相拖拽。装胎与清洁时要关注同侧前后轮的一致性。

### 0.1.2 四轮转弯为什么更难

两轮模型可以让两只轮子分别沿圆弧滚动。四只固定方向的轮子分布在前后两根轴线上，转弯时无法同时满足四个接触点都纯滚动，所以轮胎会有横向滑移和变形。

这使实际转弯能力受以下因素影响：前后轮轴距、左右轮距、车重和重心、轮胎材质、地面抓地、速度、电机输出。两侧速度差相同，在不同表面上的实际转向角速度也可能不同。

开发安排因此调整为：先用理想差速公式生成目标，再靠视觉反馈修正方向；有IMU时测量实际角速度；通过低速圆弧实验标定等效轮距。急弯提前降速，避免用突然原地旋转作为常规循迹动作。

### 0.1.3 对电机采购与安装的影响

图片显示车模已有外露小齿轮驱动轮端大齿轮的结构。更换电机必须匹配安装孔位、外形、轴径轴长、小齿轮模数/齿数及轴中心位置。图片不能读出电机具体型号，也不能证明常见JGA25-370一体减速电机可以直接装入。

因此，前面对话中“JGA25-370 12V 400～500rpm”的建议只能用于另配相应底盘的备选，不作为这台照片车模的购买结论。同款车模优先采用配套电机；确认配套电机规格后，再按总传动比换算轮端速度。

### 0.1.4 摄像头与重心

摄像头位于高支架上，有利于看见更远的线路，但振动和车身俯仰会改变图像里白线的位置及比例。支架刚度、镜头锁紧和FPC固定属于视觉调试的一部分。

电池位置在照片中不能完整确定。安装时尽量降低重心、保持左右载重对称，线缆不能碰轮胎和齿轮。不能用照片中电路板的高低位置直接推断整车重心。

### 0.2 车要跟的是一条白色胶带

赛道背景是蓝布，引导线是宽约 20±2mm 的白胶带。视觉算法要找白胶带的中心，让左侧前后轮、右侧前后轮随车身稳定地跨线行驶。这里的“左边缘、右边缘”是**同一条白胶带的两侧**，不是宽道路上的两条车道线。

四轮车不能只盯着摄像头前方一个点：前轮进入转弯时后轮还在直线上；前轮已经离开路口时后轮可能仍在路口。转向过早会切角，转向解除过早会让后轮扫过不该经过的支路。照片不能提供精确接触点位置，必须测量前后轴相对于车身参考点的距离。

赛道由折线组成，普通转角、分叉和交叉会让白色区域变宽或分成多条。到了这些位置，不能只对整片白色区域求平均中心，否则平均出来的目标可能位于没有胶带的地方。

### 0.3 按 PDF 重新核对后的规则

## 1. 从模板仓库出发，已有的是什么

## 2. 原理图决定的接口与限制

### 2.1 主控板

已解析的主板工程有“最小系统板、电源管理、外设接口”三页，核心是 CH32V307VCT6；电源包括 TPS5430 5V 降压及 MCU、摄像头、外设的 3.3V 支路。外设页包含 18P 摄像头 FPC、TFT、按键、串口、编码器和陀螺仪等接口。

原理图里有陀螺仪接口，不等于已经装有可用 IMU。拿到实物后确认模块型号、供电、通信方式和引脚。

已按两份 epro 的 MCU 引脚和 PCB 网络逐针核对，完整证据见[引脚与驱动核对](hardware/引脚与驱动核对.md)。两板对应关系以 H3 与驱动 CN5 同脚号直连为前提，机械方向仍须实测。

| 功能 | MCU 引脚 | 外设与映射 | 状态 |
|---|---|---|---|
| 左侧电机 EN | PE9 | TIM1 MAP3 CH1，20kHz | 电气网络已核对 |
| 左侧电机 PH | PE11 | GPIO | 电气网络已核对，机械极性待测 |
| 右侧电机 EN | PE14 | TIM1 MAP3 CH4，20kHz | 电气网络已核对 |
| 右侧电机 PH | PE13 | GPIO | 电气网络已核对，机械极性待测 |
| 左侧编码器 | PA0 / PA1 | TIM2 MAP0 CH1/CH2 | 引脚已核对，轮端计数待测 |
| 右侧编码器 | PD12 / PD13 | TIM4 MAP1 CH1/CH2 | 引脚已核对，轮端计数待测 |
| 摄像头 | PA6/PA4/PA5 等 | DVP，PD2/PC12 配置 | 逐针表见硬件核对，帧时序待上板 |
| 调试串口 | PB10 / PB11 | UART3 | 引脚已核对 |

同一定时器不能同时分给编码器计数和 PWM；同一 PWM 定时器的通道共享周期。相同引脚也不能同时分给摄像头、串口和电机。不要直接照抄库里某个示例的引脚。

### 2.2 驱动板如何让电机转

驱动板使用两颗 DRV8701E，每颗控制四颗外置 AOD4184A MOSFET，分别驱动左右有刷电机。控制连接器 CN5 的图示顺序为 EN_L、PH_L、PH_R、EN_R，实接时还需按连接器方向确认 1 脚。

| 信号 | 软件含义 |
|---|---|
| EN_L / EN_R | 各侧电机 PWM，通过齿轮一起作用于该侧前后轮 |
| PH_L / PH_R | 各侧电机电气方向；结合齿轮反向和镜像安装统一换算为车辆前进/后退 |
| nSLEEP | 驱动休眠控制；当前板上不是可直接假定可由 MCU 控制的急停线 |

DRV8701E 在 nSLEEP 为高时，EN=0 是低侧制动；EN=1 时，PH 选择桥的驱动方向。PWM 占空比不是严格的电机转速，也不是软件可保证的恒定输出电压。

两侧电机可能镜像安装，外齿轮啮合还会反向。同样 PH 电平未必使左右侧都朝车头转。应用层必须把“车辆前进”统一成两侧速度都为正，电气极性在底层各自修正。左侧正指令必须让左前、左后都推动车向前；右侧也分别验证。

定义一个执行器接口，本文中的名称是**拟开发接口**，不是逐飞库现成函数：

```text
motor_set(left_command, right_command)
command 范围：-1.0 到 +1.0
正数：该侧前后两轮一起推动车辆前进
负数：该侧前后两轮一起推动车辆后退
绝对值：PWM 占空比需求
0：按预先确认的制动策略输出
```

该接口内部处理限幅、左右极性、方向切换。先把输出降至零并按已确认的电流衰减策略过渡，再改变 PH 和恢复占空比，避免正反向瞬间切换。

### 2.3 当前板没有闭环电流调节

原理图中 U1/U2 的 SP、SN 接地，nFAULT、SNSOUT、SO 标为不连接。TI 手册说明 SP/SN 接地会关闭电流放大器和电流调节。因此当前板没有可供应用层直接读取的电机电流反馈，也没有接回主控的故障信号。

这不表示芯片所有保护都消失；它表示软件不能宣称自己具备电流闭环或可靠的电流限幅。PWM 限幅只能约束输出指令，不能把电流硬性限制在某个安培值。

电机电压、电机堵转电流、电池放电能力、MOSFET散热和 PCB 电流能力必须核对。首次电机验证使用限流电源，轮子离地，从低输出开始；这是针对此版电路的实际限制。

## 3. 先看懂轮子怎样使车运动

### 3.1 定义统一坐标与单位

车辆坐标：前方为 X 正，左方为 Y 正；从上往下看逆时针旋转，也就是左转，为角速度 ω 正。

- D_LF、D_LR、D_RF、D_RR：左前、左后、右前、右后轮的有效直径，单位 m。
- D_L、D_R：校准后代表左右侧的有效直径；同侧轮径差必须先处理，不能用平均值掩盖严重不一致。
- b_g：左右轮接地点中心之间的实测横向距离，单位 m，叫几何轮距。
- L：同侧前后轮轴中心之间的距离，单位 m，叫前后轮轴距。
- b：用于控制模型的轮距参数。初期取 b_g；四轮滑移车标定后可取等效轮距 b_eff。
- v_L、v_R：由各侧传动转速换算的轮胎圆周速度，单位 m/s。滑移时它们并不等于相应车身位置对地的真实速度。
- v：车身参考点的前进速度，单位 m/s；参考车取左右侧中点之间的中心作为初始近似。
- ω：车身转向角速度，单位 rad/s。

**轮距不是前后轴距。** 计算中也不要把 mm 直接当成 m。对照片中的四轮车，下面公式是用于控制的差速近似，不能当成四个轮胎完全无滑移的精确模型：

```text
v_est ≈ (v_R + v_L) / 2
ω_est ≈ (v_R - v_L) / b

给定想要的 v、ω：
v_L_target = v - ω × b / 2
v_R_target = v + ω × b / 2
```

为什么左转要右侧快：右侧位于转弯外侧，需要走更长的路。右转则左侧快。控制器最终改变两侧驱动速度，并由前后四个轮子的地面作用产生转向。v_est、ω_est 是近似估计；有IMU时将实测角速度另记为ω_measured。

四轮滑移的来源可以用一个式子解释：车身上前后位置为x的接触点，其横向速度约为 v_y+ωx。前轴x为正、后轴x为负，非零ω时不能让两个不同x处的横向速度同时为零。固定方向的四个轮子因此必须存在横向擦地或弹性变形。等效轮距是对这些影响的近似补偿，不是把滑移消除了。

### 3.2 一张表对上实际动作

| 侧速度关系 | 车辆动作 |
|---|---|
| 左右均为正，且相等 | 理想情况下前进直行 |
| 右侧比左侧快，左右均为正 | 向左画弧线；内侧左前、左后都减慢 |
| 左侧比右侧快，左右均为正 | 向右画弧线；内侧右前、右后都减慢 |
| 左侧为零、右侧前进 | 向左转，理想模型的转动中心靠近左侧；实车会擦地滑移 |
| 左侧后退、右侧前进，大小相等 | 近似原地左转，四轮会有明显横向擦地 |
| 左右均为负，且相等 | 后退 |

原地转向只用于理解执行器关系或经验证的特殊动作；照片车模的四轮擦地、齿隙和转向负载会使它与两轮车有明显区别。普通循迹优先让两侧都向前，必要时提前降低车速；禁止把原地旋转写成每个折角的默认动作。

例：**仅作算例，照片不能提供此尺寸**，b=0.14m，要求 v=0.60m/s、ω=+1rad/s：

```text
左侧前后轮：0.60 - 1×0.14/2 = 0.53m/s
右侧前后轮：0.60 + 1×0.14/2 = 0.67m/s
结果：向左转。
```

### 3.3 转弯半径、路况和最高车速

非原地转弯时，车身参考点轨迹半径 R=v/ω。若轨迹曲率 κ=1/R，则 ω=vκ。

由此得到：

```text
v_L_target = v × (1 - κb/2)
v_R_target = v × (1 + κb/2)
```

这个关系解释了三个现象：

1. 同样的弯，车速越大，所需角速度越大；只加速却不考虑转向能力，会冲出弯道。
2. 弯越急，内外轮速度差越大；外轮可能先达到转速上限。
3. 如果 b|κ|/2>1，公式会要求内侧反转。**固定κ时，单独降低v不会改变内侧目标的正负。** 应重新选择更平缓且仍满足赛道判定的目标轨迹、限制曲率，或为确有必要的低速枢转单独设计模式；不能把负数直接截成零后还宣称沿原轨迹行驶。

胶带折角的数学顶点曲率不连续。车不可能高速沿尖点瞬间改变朝向。视觉应提供一个平顺前瞻目标，让车身参考点在允许范围内平滑过角，同时关注前后四只轮子的轨迹。对照片中的四轮车，仅车身中心落在白线附近不够，前轮切角、后轮扫角也可能触发出界。

若某侧目标超过可用最高侧速度，按同一比例缩小两侧目标，尽量保持模型要求的转弯形状：

```text
peak = max(abs(vL), abs(vR))
scale = 1 if peak == 0 else min(1, side_speed_limit / peak)
vL *= scale
vR *= scale
```

左右侧能力差异较大时，还要分别检查各自上限。持续触顶说明目标车速或轨迹超出了实际能力。保持目标速度比也只保持模型中的曲率；真实地面运动仍受四轮滑移影响。

### 3.4 从转速换算车速

```text
轮子线速度 v = π × D × n_wheel / 60
```

n_wheel 是轮子每分钟转数。若编码器测电机本体轴，先除以减速比得到轮子转速；若测减速箱输出轴且轮子直接安装，不再除一次减速比。

对照片中的外露齿轮传动，还必须包含小齿轮到轮端大齿轮这一段。若电机轴小齿轮齿数为 z_p，轮端大齿轮齿数为 z_w，且没有其他减速级，则轮子转速的大小为 n_motor×z_p/z_w；若还有内部减速级，需连同计算。齿轮啮合带来的正负方向在底层极性标定时统一处理。

算例：D=65mm，轮子转速 300rpm，对应约 1.02m/s。电机商品页的空载转速不等于车落地后的可持续转速。

### 3.5 用实车标定四轮车的等效轮距

在独立训练场地，以低速给定小幅左、右差速，记录两侧编码器速度和车身实际转向角速度。实际角速度可来自校准后的IMU，也可由外部录像测量一定时间内车头转过的角度。

```text
b_eff ≈ (v_R - v_L) / ω_measured
```

避开几乎直行的样本，因为ω接近零会使估计不稳定。左右方向分别做多次，剔除起停和明显空转样本，观察不同速度下是否相近。

b_eff是便于控制的经验参数，不能代替实际几何尺寸。它可能随地面、轮胎和速度变化。没有IMU或外部测量时，先使用几何轮距和低速视觉PD闭环，保留模型误差由视觉修正，不声称已精确测得曲率。

同侧齿轮传动若存在间隙，低速反向时还会先消除齿隙再推动轮胎。环岛和普通弯道尽量采用两侧持续前进的差速动作，减少频繁换向引入的迟滞。

### 3.6 四个接触点与车身参考点

拍照俯视测量四个接触点相对车身中心的位置。初版对称近似可用左前(+L/2,+b_g/2)、左后(-L/2,+b_g/2)、右前(+L/2,-b_g/2)、右后(-L/2,-b_g/2)；实际不对称时填实测坐标。

对地面路径做几何标定后，可以把短期预测车身位置和朝向作用到这四个点，观察它们相对选定白线的位置。初期不必做复杂在线轨迹优化，用俯视录像检查前轮切角、后轮扫角也能指导前瞻和速度调整。

四个接触点检查是工程上的保守辅助，不自行改写裁判规则；十字和分叉处要相对当前选定路径判断，不能把旁边另一条白胶带误作目标。

## 4. 让软件知道轮子实际转多快

### 4.1 编码器数的是脉冲

编码器 A/B 两相的先后关系表示转动方向，累计计数反映转动角度。MT6701 需要配置为与主控接法一致的输出模式，不能把 I²C 模式直接当成 A/B 信号。

先定义 C_L、C_R：**该侧轮端实际转一整圈时，当前软件读取到的有效计数**。每侧选择一个固定轮端作为标定参考，并记录编码器实际安装在哪根轴上。

| 编码器位置 | 计数到轮端的关系 |
|---|---|
| 电机轴或其尾轴 | 包含该轴到轮端的全部减速级；C_wheel=C_encoder×i_total |
| 中间传动轴 | 只包含该中间轴到轮端的后续减速级 |
| 轮端大齿轮轴 | 通常直接得到该轮端一圈计数；按实际安装确认 |

这里C_encoder是编码器所在轴一圈的软件有效计数，i_total是编码器轴转数/轮端转数。不要把轮端齿比再重复乘入一个已经手转轮子测得的C_wheel。

照片不能确定MT6701安装在哪根轴，也不能证明编码器已随车安装。按每侧一只编码器规划两个测速通道；它们不能独立监测四个轮子的所有故障，例如电机轴仍转但某只轮端齿轮松脱。

不要直接假设 C=PPR×4。仓库 `encoder_quad_init()` 当前实现使用 `TIM_EncoderMode_TI2`，具体有效计数须结合芯片输出、接法和驱动配置实测。商品页的 PPR、CPR 也可能采用不同定义。

最直白的标定方法：

1. 整车四轮悬空、驱动不输出，给每侧参考轮端和固定支架各做一个对齐标记。先确认传动可以轻柔手转；不可强扭无法反拖的机构，可改用低速驱动和视频计圈。
2. 记录计数，手动让轮子向前转 10 圈，记录新计数。
3. 差值除以 10，得到每轮一圈的有效计数。
4. 反向转回，检查符号和计数是否相符。
5. 两侧分别完成；统一成车辆前进时两侧计数增量均为正。同侧前后轮也做标记，确认机械转数比例一致；编码器测得正常不能替代这一步。

### 4.2 计数变成距离与速度

固定周期 Δt 内读到增量 ΔN：

```text
Δs_L = π × D_L × ΔN_L / C_L
Δs_R = π × D_R × ΔN_R / C_R
v_L_measured = Δs_L / Δt
v_R_measured = Δs_R / Δt
```

例如一圈有效计数 1000、轮径 65mm，在 10ms 内读到 20 个计数，速度约 0.408m/s。这些数字只用于理解公式。

以上Δs是侧轮端按圆周算出的滚动距离。四轮转弯时本来就会横向滑移，急加速还可能纵向空转；编码器计数正常不保证车身真的走过同样距离。环岛和路口进度中的编码器里程只能辅助视觉，不作绝对位置。

### 4.3 采样周期和低速抖动

建议先用 5～10ms 速度采样周期。低速时一个周期内可能只增加零个或一个计数，直接除以很短的时间会出现速度忽大忽小。

可以使用短滑动窗口或一阶低通：

```text
v_filtered = v_filtered + α × (v_measured - v_filtered)
```

α 越小越平滑，也越迟钝。先判断抖动来自计数分辨率、线缆干扰还是机械晃动，再决定滤波强度。

读取累计计数并做正确的溢出差分，通常比“先读再清零”更容易避免清零间隙丢脉冲。具体实现仍须核对现有驱动的计数返回方式；不要把示意公式直接套到未经确认的计数格式上。

## 5. 从 PWM 开环到左右侧速度闭环

### 5.1 先做开环，确认轮子能听懂命令

四个轮子全部悬空，限制输出，从小占空比逐步增加。一次只使能一侧，记录：电机指令、该侧前后轮实际方向、编码器速度、电源电流和齿轮啮合情况。

此时要回答：左侧正指令是否使左前和左后都朝前？右侧是否同样成立？同侧两轮是否按预期同速？从多大指令开始转？前后轮是否有拖拽、齿轮跳齿？停止输出是否使该侧两轮都按预期制动？

还没回答这些问题，先不要上摄像头循迹。

### 5.2 为什么不能只给左右侧同样 PWM

同样 PWM 下，左右电机差异、两组齿轮摩擦、四只轮胎阻力、载重和电池电压都会改变侧速度。两侧速度不同，车自然就会偏。

速度闭环的目标是：无论阻力怎么变，都尽量让轮子跟上给定速度。

每侧电机独立运行一套PI，左侧一套、右侧一套，共两套。前后轮由齿轮关联，不增加四套互相争抢执行器的PI：

```text
error = target_speed - measured_speed
I += Ki × error × Δt
u_raw = u_feedforward + Kp × error + I
u = clamp(u_raw, -duty_limit, +duty_limit)
```

先从 P 开始，确认误差符号正确，再加 I 消除长期偏差。起步阶段通常不必加速度环 D。

输出已经饱和时，积分不能继续朝同一方向增长，否则轮子恢复后还会被过大的积分继续推动。用积分限幅或条件积分处理。停车、故障和重新发车时也要有明确的积分复位规则。

前馈可以由实测“侧速度—占空比”关系得到，让 PI 只修正剩余误差。左右侧可以有不同的前馈和增益。

### 5.3 调试顺序

1. 四轮悬空、低速固定目标，先调左侧，再调右侧，同时观察该侧两只轮子。
2. 小幅改变目标，观察能否跟上，有无明显来回振荡。
3. 加目标速度斜坡，避免一步跳到很高速度。
4. 在蓝布训练场地落地验证两侧相同目标速度时是否大致直行，观察四只轮子的受力与拖拽。
5. 给小幅左、右差速，记录实际转向和电流变化。四轮擦地使落地转弯负载比悬空明显增大，悬空参数只是起点。
6. 检查低速换向的齿隙迟滞，再决定是否允许正常运行时反转内侧。默认普通循迹保持两侧前进。

始终一起看目标速度、实测速度和 PWM。PWM 长期触顶且实际速度上不去，说明要求超过能力、供电不足或机械阻力异常，继续加积分不能解决。

四轮车还可能出现“两侧编码器都跟上，但车头转得比预期少”。此时速度PI已经完成了侧转速任务，问题可能是侧滑、擦地负载与等效轮距。优先降低入弯速度、核对转向模型和真实航向反馈，不要只提高速度PI积分或盲目加大PWM。

## 6. 摄像头怎样把白线变成转向依据

### 6.1 先得到可重复的图像

库默认图像为 188×120 的 uint8 数组，单帧 22560 字节；默认目标帧率 50FPS、PCLK 模式为 1。先核对相机模块版本、FPC 供电和数据引脚，再验证初始化与帧完成标志。

模板链接脚本目前是 288KB FLASH、32KB RAM；仅图像就占了大部分 RAM。启用摄像头之前列出：图像、其他全局变量、栈、堆、显示和串口缓冲。需要扩大 RAM 分区时，同步核对链接脚本与芯片分区配置，不能只改 `LENGTH`。

不需要额外保存一张完整的 8 位二值图：可逐行处理，或用位压缩存储。若确实需要双灰度缓冲，两个 188×120 缓冲共 45120 字节，32KB RAM 显然不够，还要另外给应用留空间。

### 6.2 防止读到前后两帧拼起来的图

仓库摄像头驱动使用循环采集。帧完成标志置位，不代表随后整个算法期间该缓冲永远不再更新。

必须设计清楚图像所有权：通过适当暂停采集、受控缓冲切换，或在保证时间窗口内复制需要的 ROI 等方法，确保算法处理的是一致帧。选择哪种方式，要结合 RAM 和实际采集时序确认。

每次发布视觉结果带时间戳。控制器能知道“这份结果已经过时”，不要永远拿最后一张图继续高速开车。

### 6.3 先标定安装，再谈参数

- 摄像头固定在车体上，镜头锁紧；安装歪斜会直接产生长期偏差。
- 在车正对直线、左右两侧前后轮对称跨线时记录图像中的白线中心，作为零偏参考。
- 沿图像从近到远记录白带宽度；同一条 20mm 白带在远处像素更窄。
- 记录不同图像行大致对应车前多少距离。初期可用尺子和地面标记实测。
- 调整曝光和增益，使白线与蓝布灰度有稳定差异，避免大块反光变成白色。

图像常用横坐标向右为正，纵坐标向下为正；这与车辆左向为正的坐标不同，转向符号必须明确。

对照片的高支架结构，需测量相机相对车身中心的前后偏移、高度与俯角。地面标定后的目标点先从相机地面坐标变换到车身参考点坐标，再参与几何跟踪。初版图像PD可先标定直行零偏和各行前瞻距离；它仍需要在相机重新安装后复核。

车头振动会让整片地面图像一起上下跳，而真实急弯通常表现为线形变化。先固定支架、降低机械振动、观察一致帧，再调视觉导数；强行滤平所有变化会把真正的弯道也延迟。摄像头若看不到前轴附近胶带，当前后轮是否过角需结合已走里程和录像标定，不能把图像底边直接当成车身中心。

### 6.4 提取白胶带

初版流程：裁掉天空、车身等无用区域，选择地面 ROI，对灰度做阈值分割，再从下往上扫描连续白色段。

```text
灰度大于阈值 T → 白线候选
每一行找到连续白段 [x_left, x_right]
宽度 width = x_right - x_left + 1
中心 center = (x_left + x_right) / 2
```

候选白段要同时考虑：

1. 宽度是否在该行允许的范围内。
2. 与上一行已选中心是否连续。
3. 与上一帧预测位置是否相近。
4. 该段是否属于当前状态选定的支路。

不要永远选最长白段；十字横线恰好可能是最长的。也不要把多个分叉段平均成一条线。

先把手动阈值跑通，再考虑基于局部亮度或直方图的自适应阈值。阈值更新要平滑，避免每帧大幅跳变。

### 6.5 发布一份有意义的视觉结果

视觉模块至少输出：

```text
结果时间戳
近、中、远处的线中心与是否有效
主线方向趋势
各扫描行白段数量、宽度和连续性
候选支路及其方向
有效行数量与识别置信度
```

置信度应反映找到的线是否连续、宽度是否合理、是否存在分叉歧义。一个孤立的亮斑不能因为很亮就得到高置信度。

## 7. 白线在右边时，左右两组轮子究竟怎么转

### 7.1 从横向偏差起步

定义图像归一化误差：

```text
e_right = (selected_center_x - calibrated_center_x) / (image_width/2)
```

e_right>0 表示白线在车前右侧，需要向右修正。本文 ω 正代表左转，因此最初控制可写为：

```text
ω_raw = -(Kp_visual × e_right + Kd_visual × de_right/dt)
```

**右偏差 → ω需求为负 → 左侧前后轮更快、右侧前后轮更慢 → 四轮与地面共同作用使车头右转。** 实际转向量还会受滑移影响，需要视觉持续反馈。

把整车四轮架空且相机仍能看见地面白线，横向调整白线或整车位置，查看控制输出与四轮方向，验证这个符号链。落地后再验证实际朝向修正，避免把“输出符号正确”误认为“地面转向已经标定”。

### 7.2 近处负责不掉线，远处负责提前知道弯

可对多个有效行做加权得到前瞻目标：

```text
e = sum(weight_i × e_i) / sum(valid_weight_i)
```

近处信息反映当前是否偏离，远处信息帮助提前转弯。车速高时前瞻距离通常需要增加，但太远可能把折角切过去。

直道里近、中、远中心相近；弯道里远处中心逐渐向一边偏。只有近处中心而没有方向趋势时，很容易到弯角才突然猛打差速。

### 7.3 第一版用视觉 PD，I 谨慎加入

视觉 D 要按真实视觉时间间隔计算，并适当滤波；像素跳变直接求导会让轮子抖动。进入分叉、交叉或重新找到线时，目标可能突变，应重置或约束导数状态。

长期偏差先查摄像头安装、轮径标定、左右速度闭环和轮胎差异。视觉 I 如需加入，应弱一些，并在元素切换、停车、丢线时受控处理。

### 7.4 标定地面坐标后，再考虑几何跟踪

如果知道前瞻点在车体坐标中的位置：前方距离 X、左侧距离 Y，可以采用几何追踪：

```text
κ = 2Y / (X² + Y²)
ω = v × κ
```

Y>0 时目标在左边，κ和ω都为正，车左转。这能直接与轮子运动学连接。

这里的X、Y必须是相对车身参考点的地面长度坐标，已包含相机安装偏移。不能把图像像素直接放进公式，再声称得到单位为1/m的曲率。对四轮滑移车，该公式提供转向需求，实际转向仍由视觉或航向反馈校正。初版先使用图像误差PD；有安装标定后再评估几何跟踪，单次实验只使用一套主转向控制方法。

### 7.5 让视觉PD服从四轮车的可执行范围

前述ω_raw只是一份转向需求。给定前进速度v后，普通循迹模式应限制内侧不反转，并预留一定驱动余量。设0≤η<1为内侧最低速度占v的比例：

```text
当v>0时：
omega_limit = 2 × (1-η) × v / b_eff
omega_cmd = clamp(omega_raw, -omega_limit, +omega_limit)
vL_target = v - omega_cmd × b_eff/2
vR_target = v + omega_cmd × b_eff/2
```

η由实车低速实验决定，不在文档中假定数值。初期尚未标定b_eff时使用b_g作为起点。接近停车时令v和ω共同收敛到零；禁止v已经降至零却仍保留旧ω，导致车突然原地反向旋转。

如果视觉长期要求超过可执行范围，意味着当前目标路径过急、前瞻选择不当或地面模型有误。控制限幅只是保护执行过程，不能保证仍能过弯；需要提前规划可行路径，必要时停车，不能靠更大积分硬顶。

有可用IMU并验证采样后，可以在视觉给出ω目标和两侧速度目标之间增加受限的角速度反馈，修正ω_measured与ω_target的偏差，再由两个侧速度PI执行。先用视觉外环和两侧PI跑通，再评估这一层；它没有测量真实纵向对地速度的能力，也不能让四轮滑移模型变得完全精确。

## 8. 把速度和路况对应起来

速度规划输出前进速度v，方向控制输出ω需求，约束模块共同处理后生成左右侧目标。两个侧速度PI再把目标变成两路PWM；齿轮把每侧输出传到该侧前后轮。

| 路况 | 视觉线索 | 车身动作 | 四轮/两侧驱动表现 |
|---|---|---|---|
| 直道 | 单条连续白带，近远方向稳定 | 稳定后逐渐提速 | 两侧目标接近；同侧前后轮机械同步 |
| 左弯 | 远处白带向左偏 | 提前减速、左转 | 右侧两轮快、左侧两轮慢；实际偏航受四轮擦地影响 |
| 右弯 | 远处白带向右偏 | 提前减速、右转 | 左侧两轮快、右侧两轮慢；检查转向余量 |
| 折角 | 远近方向变化明显，线可能接近视野边界 | 先减速，选择平顺且可行的过角路径 | 避免内侧无意反转和外侧饱和，检查四轮轨迹 |
| 十字 | 横向白带使局部变宽，同时有前方延续 | 沿进入方向直行通过 | 两侧持续调速保航向；后轴通过后解除路口锁定 |
| Y 分叉 | 连续多行出现分开的候选线 | 锁定本次选择的一支 | 两侧差速带前轮进入目标支路，并让后轮跟随通过 |
| Y 合流 | 两条候选线收敛为一条 | 保持支路连续性，确认车身已通过 | 图像恢复单线后仍检查后轴进度，再恢复高速 |
| 环岛 | 分支/合流及闭环形状 | 进入、沿环走、确认绕完、退出 | 环道持续差速，角点降速；切出时保留后轮通过余量 |
| 低置信度/图像过期 | 线不连续或没有新帧 | 降速；短暂保持合理方向，超时停车 | 禁止因错误中心突然满差速 |

没有可靠地面曲率时，可以按远近方向差、视觉误差、置信度和元素状态查表设定速度档。标定地面曲率后，可参考横向加速度关系 a_y=v²|κ| 设置弯道速度上限。

加减速要有斜坡，并在看见前方折角时提前减速。不能等轮子已经冲过角点才靠强制动补救。具体速度上限由轮胎抓地、相机视野、控制延迟和电机能力实测决定。

四轮滑移车还需限制侧目标变化率和转向需求变化率，避免齿轮传动及轮胎受力突然翻转。发生停车、降速时，速度与转向限制要一起更新，遵守第7.5节的普通前进模式约束。对同一条给定曲率的路径，减速能降低动态负荷，但不能改变所需左右速度比，也不能凭空解决结构转不过去的问题。

首次落地用录像标定“看见角点→开始减速→前轮进入角点→后轮通过”的相对时机。这个时机包含相机前后偏移、前瞻距离、帧延迟和制动距离，不用一个固定帧数代替所有速度下的判断。

## 9. 十字、Y 岔路和环岛分别处理

### 9.1 十字路口：锁住进入方向，直行

白胶带交叉时，横向胶带可能占满若干图像行。普通“最宽白段中心”会把车拉向旁边。

进入十字候选状态前保存进入方向。用路口前后的线连续性、前方线段和必要的短程里程/航向信息，预测直行路径。暂时被横线遮住的行不参与普通中心平均。

```text
NORMAL
→ 连续观察到交叉结构
→ CROSS_APPROACH：降低速度，保存进入方向
→ CROSS_PASS：选择与进入方向连续的前方路径
→ 单条白线持续恢复，结合路口位置估计确认后轴也已通过
→ NORMAL
```

“直行”是保持进入方向的轨迹，不是永远把左右PWM写成相等。两侧仍然需要速度反馈；四轮擦地和左右载重差异都可能产生偏航。

摄像头位于高支架上并看向前方，画面中的十字消失时它可能还在前轴前方，也可能已被车身遮挡。先标定十字在不同图像行对应的车身前方位置，用累计路程辅助估计后轴进度，并在出口线稳定后解除锁定。编码器路程受滑移影响，因此这一条件要用录像标定余量，不声称单靠路程即可严格证明后轴过线。

### 9.2 Y 岔路：选中一支后持续跟随

分叉候选必须连续出现，并且分支之间有几何分离。单帧噪点或白线短暂变宽，不能直接触发一次岔路事件。

```text
NORMAL
→ Y_CONFIRM：确认两支候选
→ Y_SELECT：根据该岔路的历史选择 A 或 B
→ Y_COMMITTED：持续跟随已选的一支
→ Y_MERGE：确认重新合并成单线
→ Y_CLEAR：出口单线稳定，结合位置与里程辅助确认后轴通过，解除本次锁定
→ NORMAL
```

如果某一圈选择了左支，不能每一帧重新选“当前最靠左白段”，否则合流处可能换线。应持续跟踪上一次选中路径的空间连续性。

对四轮车，选中支路以后要持续检查前后轮的转弯空间。前轮刚对准新支路时不能马上结束转向状态或提速；后轮可能仍处于分叉中心。角度较大的分叉需要较早减速和足够的视觉前瞻，路线还需满足第7.5节的侧速度约束。

只有一个 Y 元素时，可通过“已成功通过次数”安排第一次 A、第二次 B。计数必须在通过并离开之后更新，一次路口看见十帧仍只算一次。

若有多个 Y 元素，全局奇偶切换会出错。例如每圈两个岔路，第二圈第一个仍可能选第一圈相同支路。此时需要给不同岔路分配事件顺序或身份，分别保存历史。身份可结合元素序列、粗略里程、进入方向等信息，正式布局的数量与规则需先确认。

局部画面通常无法知道左右哪支更短。A/B 表示入口处可以一致区分的两支，不宣称已识别“长路/短路”。

### 9.3 环岛：绕一周是路径任务

仅看“白线分成两支”不能可靠区分 Y 岔路和环岛。识别需要入口拓扑、后续闭环形状、转向过程和现场元素结构共同支持。

建议状态：

```text
NORMAL
→ ISLAND_CONFIRM：确认环岛入口结构
→ ISLAND_ENTER：选择进入环道的路径
→ ISLAND_FOLLOW：沿环道跟踪，经过第一次出口机会时继续绕行
→ ISLAND_LAP_CONFIRMED：已有足够证据说明完成一周
→ ISLAND_EXIT：选择正确出口
→ ISLAND_CLEAR：出口稳定，辅助确认后轴离开分支区域，再解除锁定
→ NORMAL
```

在环道中依然跟可见胶带。状态机只是决定路口处继续沿环还是离开，不应长期依靠固定 PWM 盲转。

六边形环道会连续出现折角，四轮车的前轮过角和后轮扫角会反复发生。保持较低环内速度，预览下一个角，侧速度不要每到角点都突然正反切换。环岛退出需要车身转向出口并让后轮通过，不能把相机第一次看见出口当成整车已经离环。

“完成一周”的证据按可靠程度组合：

- 再次看见可辨认的入口/出口拓扑，且状态顺序一致。
- 沿正确方向有完整绕行过程，里程超过最小环行距离。
- 如有 IMU，累计有符号转角与该结构的一周过程相符。
- 六边形角点序列可作辅助，但一个角可能在多帧重复出现，不能每帧加一；也可能因相机视野漏检。

不能只把“陀螺仪积分超过 360°”作为退出条件。进入和退出本身也会改变朝向，打滑、识别错误和漂移都会干扰判断。进入时定义统计起点，并以视觉拓扑验证退出机会。

若没有足够证据确认一周，维持低速沿环比过早漏绕更符合该罚时规则；仍须设置异常时间或路程上限，避免程序永久卡在环内。

### 9.4 元素切换要防抖

每个事件都要有确认、提交、完成和离开后的解除锁定。确认可用连续帧/时间；解除锁定还可结合走过的距离。

阈值是实测参数，不能把本文中的流程当成已适配现场的识别器。保存现场典型帧，再验证状态切换是否与真实路况相符。

### 9.5 丢线与遮挡

低置信度不等于立刻换到另一条亮线。先按当前状态排除十字、岔路或环岛导致的正常缺失。

短时缺失时减速，并有限保持最近可靠的方向趋势；限制保持时间和差速幅度。持续无可靠线或图像超时后进入停车。任何恢复动作都不能保证已经出界的成绩重新有效。

该车有四个接地点，禁止把“左侧前进、右侧后退大幅扫一圈”作为默认搜索。先按受限曲率保持最近可靠路径，随速度下降同步减小角速度需求，必要时制动停车；既要避免侧驱动突然反转，也要避免后轮横扫支路。

## 10. 程序怎样按固定时间工作

推荐先用裸机周期调度。下面的周期是开发初值，不是已测得的性能：

| 工作 | 初始安排 | 原因 |
|---|---|---|
| 编码器采样、速度 PI、PWM更新 | 5～10ms 固定周期 | 轮速反馈需要稳定节拍 |
| 图像处理、元素识别 | 每个一致的新帧处理一次，目标约50Hz | 新图像才提供新的道路信息 |
| 目标速度斜坡、视觉结果超时检查 | 随控制周期执行 | 加减速与停车不应等屏幕刷新 |
| IMU采样（如安装） | 按器件能力和总线预算，独立周期 | 不能被图像显示阻塞 |
| 屏幕、参数菜单 | 约5～10Hz，运行时可更低 | 屏幕刷新不需要占用主控制时序 |
| 调试日志 | 限速发送，禁止控制中断内阻塞打印 | 防止串口把控制周期拖长 |

中断只做有确定执行时间的工作：计数采样、短控制计算、必要标志和外设处理。图像扫描和整屏刷新放主循环。主循环可能忙，不应负责没有时间保证的速度采样。

若某次主循环没有拿到新图，不能用同一张图重复计算“视觉导数”。控制器继续执行轮速闭环，同时依据结果年龄决定是否降速或停车。

当图像算法更新多个共享字段时，要发布一个完整快照，避免控制中断读到“一半新目标、一半旧目标”。长时间关中断也不可取，采用短临界区或经过设计的快照切换。

建议始终测量：控制周期抖动、单帧处理时间、图像结果年龄、丢帧次数、栈和堆余量。

数据只向清楚的方向传递：

```text
新图像 → 候选白线与分支 → 元素状态选定路径
      → 计算v、ω需求 → 应用前进模式/曲率/变化率约束 → 分配左右侧目标速度
      → 两侧PI结合编码器实测速度 → 两侧PH/EN
```

视觉模块不直接写 PWM；轮速 PI 不决定走哪条岔路；底层电机模块不判断环岛。这样遇到问题时，可以定位是哪一层的输入或输出错了。

调度示意如下，名称是逻辑说明，不是可以直接编译的代码：

```text
初始化：
  建立安全电机输出状态
  初始化时钟、调试、编码器、控制节拍
  加载并校验参数
  初始化摄像头及可选IMU
  确认传感器与参数有效 → 进入静态调试/待发车

控制节拍：
  读取两侧计数增量、更新实测速度
  检查运行状态与视觉结果年龄
  对v、ω需求作相互一致的限制和过渡；停车时ω随v归零
  用b_eff或初始b_g分配左右侧目标，处理侧速度上限
  运行两侧速度PI
  更新PH/EN

主循环：
  有一致的新帧时：
    提取白线候选
    更新路况状态并选择目标路径
    计算方向和速度需求
    完整发布带时间戳的目标
  按低频节拍更新屏幕和日志
  仅在允许调参的模式处理参数修改
```

## 12. 按这个顺序开发，每一步都能看见结果

### 第零步：先落实照片中的机械关系

在四轮悬空、驱动不输出时检查每侧小齿轮与前后大齿轮的啮合，标记四个轮子。记录实际电机位置、每侧总传动比和编码器所在轴；测量四轮有效直径、几何轮距、前后轴距及相机安装偏移。

检查同侧轮端是否松动、齿轮是否偏心或跳齿、前后轮是否相互拖拽。如果机械关系不成立，先修正机械问题，不让PI积分去补偿卡滞。

完成标志：能画出两条从PH/EN到电机、齿轮、前后轮、编码器的对应链；尺寸和待测项有记录。照片无法读取的型号和齿数不填猜测值。

### 第一步：模板能上板运行

保留现有时钟和调试初始化，先验证启动信息和主循环计数。确认所用调试口与模板的 UART3 PB10/PB11 对应，保留 PA13/PA14 调试功能。

完成标志：复位后能稳定进入程序；没有电机动作；知道如何重新烧录和恢复到模板。

### 第二步：单独控制电机

四轮全部悬空，完成PH/EN输出、各侧方向修正和低输出限制。依次验证左侧正、右侧正、左侧负、右侧负、零指令；每次观察该侧前后两轮。后续落地差速验证只在训练场地低速进行。

完成标志：两侧各自正指令都使同侧前后轮推动车辆前进；前后轮比例符合机械传动，停止与方向过渡符合已确认的驱动逻辑。

### 第三步：读取并标定编码器

先确认可反拖性，再手转或低速电动计圈，测两侧轮端一圈的有效计数、符号和速度变化。按编码器所在轴核对齿比，防止重复换算；同时用前后轮标记检查同侧联动。

完成标志：轮子正转计数为正；能从计数换算出合理转速；正反转和连续多圈无明显丢计数。

### 第四步：完成两套侧速度PI，并落地标定转向

先单侧悬空低速，再两侧同速，最后在蓝布训练场地给小幅差速。每侧只运行一套速度PI。为目标加斜坡、为积分加防饱和；观察前后轮拖拽和转向负载，记录目标、实际、PWM三条量。

完成左右圆弧低速实验，借助IMU或录像对照真实偏航，评估b_eff与转向死区。没有航向测量时保留b_g作为起点，标注模型未标定，不依靠编码器推算“准确转过了多少角度”。

完成标志：两侧速度跟随可重复，落地转向方向正确；知道相同差速在实际地面产生的大致转弯效果，输出限幅和换向策略明确。悬空速度PI通过不代表落地转向通过。

### 第五步：只看图，不让图控制电机

检查相机帧一致性、高支架固定、俯角、安装偏移、曝光和阈值。标定若干图像行相对前轴/车身中心的地面距离。在屏幕上叠加白段边缘、所选中心、前瞻点、置信度和候选路况。

完成标志：直线、左弯、右弯、十字、Y、环岛入口的选线结果能与人眼对应；错误帧能保存或重现。

### 第六步：低速直道循迹

将前瞻误差接入视觉 P，验证右偏差到右转的符号链。再逐步加 D，观察方向是否平稳。

完成标志：轻微偏移后能回到白线附近；不出现越修越偏或持续蛇形。

### 第七步：加入弯道和折角

增加远处方向信息、前瞻距离和弯道降速，应用内侧前进、外侧速度上限与转向变化率约束。录像检查前轮开始转弯和后轮离开角点的过程，必要时调整目标曲线与入弯时机。先固定低速解决选线，再增加速度规划。

完成标志：左右弯、连续换向、折角均能通过；四轮轨迹符合现场判定，外侧不长期饱和、内侧不发生未经设计的反转。编码器达标却实际转向不足时，已能区分滑移/传动问题和速度环问题。

### 第八步：先十字，再Y，最后环岛

每个元素先独立摆放验证，再放进闭环赛道。十字验证前后两轴都直行通过后再解除锁定；Y验证两次访问选不同支路、前轮入支路与后轮退出都稳定；环岛验证完整一周、出口选择和后轴离环顺序。

完成标志：屏幕状态与真实元素相符；不会因相机提前看见出口而过早恢复普通循迹；同一元素多帧不重复计数，不因前后轴通过时间差卡死或误重入。

### 第九步：两圈任务与陌生布局

使用不同的直线长度、左右方向、灯光和元素间距，记录两圈内各元素的实际通过顺序、分支选择和失误位置。

不要用“运行了某个秒数”直接代表一圈，也不要未经确认把第二次遇到某个元素当作已经到终点。比赛计时由外部计时器完成，车载停车需要独立的终点识别依据；若现场没有标记，应先确定比赛结束后的安全接车/停车流程。

完成标志：能连续完成两圈；按要求通过两条支路与环岛；十字直行；运行过程不依赖外部修改参数。

### 第十步：提速和正式流程

准备保守完赛档和提速档。优先缩短直道加速等待、提前识别弯道、减少环岛重复绕行，再提高峰值速度。

比赛前静态检查图像、参数、轮胎与电池；获得许可后发车。开跑后禁用改变运行状态的通信入口。赛后结合录像和车载记录定位失误，并按规则确认成绩。

## 13. 一眼判断常见问题

| 现象 | 先看什么 | 常见原因 |
|---|---|---|
| 一偏就越偏越远 | 图像误差、ω符号、左右侧目标 | 图像右正与车辆左正没有转换，或左右电机映射反了 |
| 左右同样PWM却不直 | 左右实测速率 | 电机、轮径、负载差异；尚未做速度闭环 |
| 两侧编码器速度相同仍慢慢偏 | 四轮直径、传动、载重和轮胎抓地 | 轮径换算不准、同侧前后拖拽、滑移或机械不对称 |
| 来回蛇形 | 视觉误差与轮速变化 | 视觉P偏大、前瞻不合适、延迟/导数噪声 |
| 直道正常、急弯冲出去 | 远处方向、入弯速度、外轮PWM | 预判太晚、速度过高、外轮到上限 |
| 十字突然转向 | 白段选择和元素状态 | 横线被当作主线；未保持进入方向 |
| Y处在两支之间摇摆 | 选中支路标识 | 每帧重新选路、没有提交状态 |
| 岔路计数突然增加很多 | 事件确认与解除条件 | 把多帧观察当成多次经过 |
| 环岛绕不完就出去 | 绕行完成证据 | 第一次出口机会就退出，或只靠定时判断 |
| 画面撕裂、选线偶发跳变 | 缓冲所有权与帧时间戳 | DMA在算法读图时覆盖同一缓冲 |
| 同侧前后轮拖拽、齿轮响 | 四轮直径、轮端紧固、啮合与轴承 | 同侧轮径不一致、齿轮偏心/松脱或机械卡滞 |
| 两侧速度跟上但转不过弯 | 实际航向、等效轮距、轮胎地面状态 | 四轮擦地、模型不匹配或路径曲率超出可执行范围 |
| 一降速就突然原地旋转 | v与ω限制是否同步 | v归零而保留旧ω，分配出一侧正一侧负 |
| 换方向后先空动再猛转 | 电机计数、轮端标记、PI积分 | 齿隙迟滞与积分堆积 |
| 前轮过了路口，后轮却切错支路 | 解除路口锁定的位置 | 相机前瞻和前后轴距没有落实到通过进度 |
| 路面图像随加减速整体跳动 | 相机杆刚度、俯仰、FPC牵拉 | 高支架振动被误认为道路转弯 |
| 输出满了但速度上不去 | 电压、机械阻力、负载 | 超过电机能力、供电压降、轮子卡滞；不能靠加积分解决 |
| 开电机主控复位或摄像头断帧 | 电源与共地回路 | 起动电流、噪声、接线和供电问题 |

## 14. 必须记录的参数与验收数据

物理参数：四只轮子的有效直径与同侧一致性、几何轮距、前后轮轴距、等效轮距、全部传动级的减速比、小齿轮与轮端齿轮齿数、编码器有效每轮计数、电机额定电压与堵转电流、整车质量、相机安装位置。

控制参数：控制周期、测速滤波、左右PI、前馈、占空比上限、速度斜坡、视觉P/D、前瞻位置、路况速度档、图像超时时间。

视觉参数：分辨率、曝光、增益、阈值、ROI、每行合理线宽、候选连续性范围、元素确认与离开条件。

建议每条运行记录包含：时间、运行模式、元素状态、视觉置信度和图像年龄、前瞻误差、v/ω需求、左右目标与实测速度、左右PWM、分支选择历史。日志须限速，避免日志自身改变控制行为。

验收依据：

| 层次 | 应看到的结果 |
|---|---|
| 电气与执行 | 左右方向正确，启停可控，电源与器件工作状态正常 |
| 四轮传动 | 一侧指令对应同侧前后轮，机械同步、轮径一致性和编码器安装轴明确 |
| 测速与速度环 | 计数比例实测，单位一致，轮速能跟随低速目标 |
| 滑移与转向 | 在实际蓝布地面验证左右圆弧；实测航向与模型误差有记录，普通模式不意外反转 |
| 图像与时间 | 帧一致，无长期过期图像，处理时间不挤占轮速控制 |
| 普通路况 | 直道、左右弯、折角稳定循迹，录像包含前轮切角和后轮扫角检查 |
| 元素 | 十字直行，Y分别选两支，环岛完成一周；解除状态时机考虑后轴通过 |
| 完整任务 | 两圈连续有效运行，满足现场判定，发车后没有通信干涉 |
