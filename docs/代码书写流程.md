# 代码书写、构建与上板流程

当前固件V1.2，2026-11-01更新。本文按当前分层工程说明开发顺序和验收方法。

## 先分清你现在从哪里开始

如果只是运行本仓库，不必把所有文件重新写一遍：先执行第3节电脑测试与编译，再按第4节完成实物标定。如果是学习“从空模板怎么写出来”，按下面的阶段顺序逐个实现。

默认固件不能发车是预期行为：实际轮径、轮端计数、机械方向和新视觉时序尚未填好。编译成功只说明源码能生成芯片程序。

### 每完成一阶段，都应该看到什么

| 阶段 | 主要文件/改动 | 完成标准 | 不通过先查 |
|---|---|---|---|
| 1. 电脑工程 | tools/build.py、tools/test_host.py | 脚本成功退出，出现当次BUILD PASS和测试PASS | 工具链路径、WCH版本、头文件目录 |
| 2. 上电零输出 | User/board/board_port.c、board_config.h | 架空时上电不转，EN为0 | EN/PH次序、H3与CN5脚号、重复初始化 |
| 3. 看计数 | User/control/side_encoder.c | 手转一整圈得到可重复计数，前进方向为正 | A/B接线、编码器供电、符号、齿比 |
| 4. 测速与PI | User/config/control_tuning.h | 专用低速测试中测量速度逐步接近目标，不持续振荡 | 轮端计数、轮径、方向，之后再看P/I |
| 5. 看清一帧 | User/board/camera_frame.c | 静态二值图完整且稳定，处理期不被新图覆盖 | 排线、曝光、DVP暂停重启、图像方向 |
| 6. 视觉输出 | User/vision/vision_pipeline.c | 白线在右时direction_rad为正；黑图返回无效 | 图像镜像、种子选路、目标位置和有效性 |
| 7. 接电控 | User/control/path_control.c | 右目标给负omega，最终左侧目标比右侧大 | 方向符号、会话号、帧时间、限幅 |
| 8. 落地与元素 | User/config/vision_tuning.h、track_profile.h | 普通路稳定后，逐个验证十字、Y、环岛及两圈记录 | 先回放视觉选路，再查控制和轮胎滑移 |

第4阶段的“专用低速测试”需要开发者临时编写架空测试入口，本仓库没有可按一下就强制转动的校准菜单。不要靠乱填标定位来跳过正常发车检查。

每阶段先通过再继续。否则例如测速方向本来反了，靠加大PI参数只会把错误放大。

## 1. 从模板到当前工程

固定起点为 `mode-for-ch32v307vct@7673725bab177202212c43a409d778aab45c5fab`。保留WCH/逐飞库及启动，应用分为vision/control/board/integration/shared/config。先读[项目结构与参数](项目结构与主流程参数说明.md)，目录和函数均对应实际源码。

1. 在 `User/board/board_config.h` 按epro确定EN/PH/编码器映射，在 `board_port.c` 封装硬件。EN先拉低再选PWM，主函数保持一次零输出初始化。
2. 在 `User/control/side_encoder.c` 做16位连续CNT差分，换算轮端速度与里程；不要每周期清CNT。用实测轮端一圈有效计数，不能默认PPR×4。
3. 在control下写速度PI、方向PD和差速约束；先电脑边界测试，再低速架空验证方向、占空比和计数。
4. 在board下完成DVP单帧借用/归还，实际暂停接收和DMA，归还后重启并丢弃首帧，验证缓冲不会被处理期覆盖。
5. 在vision下实现Otsu、连通道路、外轮廓、截断区间、折点和候选路径，再接多帧元素状态、路线历史及目标几何。
6. 通过 `VisionOutput` 接control方向PD，主循环发布MotionRequest，TIM6固定5ms执行运动规划、测速PI和PWM。
7. 将视觉和电控默认值分别放在 `User/config/vision_tuning.h` 与 `control_tuning.h`，由共享参数代码统一校验、序列化。
8. 接本地按键、静态诊断和双槽Flash保存；无效图像、超时、非有限数和错误会话不能被当成有效运行目标。

## 2. 两套算法独立开发

视觉入口 `vision_pipeline_step` 返回VisionOutput，提供方向角/像素距离、帧/会话、有效性、速度建议和停车标记。视觉侧不生成车体角速度，不写PWM。替换识别方法时维持该协议；诊断用VisionFeatures不传给电控。

电控入口 `control_path_step` 只消费VisionOutput，方向PD输出车体角速度；`motion_plan_step` 换算左右目标并限幅，`speed_pi_step` 输出EN占空比。可以分别替换方向、规划或速度算法。保持停止传播、会话检查和陈旧帧保护。

识别参数改vision_tuning；方向PD、两侧速度PI与运动限幅改control_tuning。实际几何/编码器数据改vehicle_calibration，现场路线改track_profile。有效Flash记录会覆盖编译默认值，调参后确认实际加载的是哪一组参数。

## 3. 电脑构建

从仓库根目录执行，Python3.9+：

```powershell
python tools/test_host.py --cc C:/mingw64/bin/gcc.exe
python tools/build.py --toolchain "E:/RISC-V/MounRiver_Studio3/resources/app/resources/win32/components/WCH/Toolchain/RISC-V Embedded GCC/bin"
```

测试包含两组完整回归和两套独立链接测试。目标脚本递归扫描User并加入全部头目录，使用WCH GCC8.2、rv32imafcxw/ilp32f、D8C启动和逐飞配置静态库。失败非零退出；新构建开始时移除当前版本旧产物，避免把旧HEX当新结果。

当前输出 `build/target/second-test-v1.2.elf/.hex/.bin/.map` 与构建报告，主机测试报告位于build/host，已验证快照位于release/v1.2。新应用使用Wall/Wextra/Werror，第三方库原有警告如实记录。用户改变代码后应重新构建，不直接使用历史release。

MounRiver导入根目录.project或打开.mrs/CH32V307VCT.mrs-workspace；头目录和测试排除已配置。本次验证的是CLI，GUI编译、下载和实车效果未验证。

## 4. 上板顺序

1. 架空四轮，确认共地、线束脚号和上电EN=0；原理图对应见[硬件核对](hardware/引脚与驱动核对.md)。
2. 查看UART3 PB10/PB11、115200日志与屏幕；静态右键看Otsu二值图，检查完整帧、曝光、镜像、重启缺行。
3. 手转两侧轮子，测轮端一圈计数及正负号；填轮径、轮距、轴距和计数。
4. 专用低占空比架空测试确认PH机械前进方向，再恢复正式入口；先P后I调轮速，逐侧观察速度、发热与齿轮啮合。
5. 测相机前移距离及近远采样行对应前向距离；确认中断/图像最坏耗时、栈余量、方向PD符号与增益。
6. 依次验证直线、普通弯/直角弯、十字直行、分叉两支、环岛进入/一周/退出和后轴清出。
7. 填现场事件顺序和终点距离，验证两圈记录；完成全部条件后才设CAL_MASK、CAL_CAPTURE_VALIDATED和CAL_VISION_V2_VALIDATED。完整比赛还需CAL_FULL_RACE与有效现场路线。

默认实测值和新版视觉开关为0，上电STATIC、禁止发车。中键准备，KEY1开始，KEY2停止/清故障；下键长按保存仅允许静态且静止，保存后复位。软件按键停止不替代硬件断电措施。

## 5. 结果如何解释

当前已验证目标编译、电脑算法案例与独立链接。没有烧录或实车成绩。像素距离未转为米，未参与自动距离减速；外轮廓/环岛与折点策略现有边界见[视觉实现说明](视觉链路实现说明.md)。每次算法、尺寸或场地变化后重新做相应标定。
