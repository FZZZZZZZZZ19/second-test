# 代码书写、构建与上板流程

V1.50.23按装车观察修正电机左右归属。左编码器手转对应I1，当前右轮转而I1=0、I3约3.3m/s，软件PWM左25%右0%。据此将车体左电机输出设为PE14/PH PE13，车体右电机设为PE9/PH PE11；编码器继续左TIM2、右TIM4。方向电平两侧0，编码器符号左-1、右+1。参数格式沿用11。

V1.50.22将默认speed limit提高到5m/s，VOFA target允许0～5m/s，进入闭环要求目标大于0且不超过当前speed limit。编码器测速允许-5～+5m/s，超过该范围判异常。加载旧格式2/4/5/6/7/8/9/10时，将已通过合法性检查的速度上限更新为5，目标速度等其他字段保持保存值。停车保存为格式11后，后续菜单设定的速度上限继续生效。

V1.50.21依据最新台架反馈修正。用户报告V1.50.20运行run 30时两侧均后转，左测速负、右测速正。本版前进PH设为左0、右0，编码器符号设为左-1、右+1，预期两侧前进测速均正。参数格式10迁移旧2/4/5/6/7/8/9中的方向，保留其他参数。主菜单显示完整版本V1.50.21，停车保存一次可持久化方向。

V1.50.19按实测反馈调整保存阈值，两侧速度绝对值均小于0.5m/s时允许保存，仍要求停车模式和零PWM。control菜单新增run 5，左右固定5%占空比，stop或返回停止。run 30固定30%，vofa运行速度闭环。菜单顺序为run 30、image、vofa、VOFA target、stop、run 5、back。

V1.50.18修复VOFA target保存。保存检查STATIC模式、零PWM及反馈速度绝对值小于0.5m/s，允许停车时原始计数抖动，已移除额外500ms等待。VOFA只启动速度闭环，要求参数合法、编码器反馈有效和目标大于0。独立run 30提供30%开环调试。比赛start的完整标定检查继续生效。

V1.50.17编码器方向实测更新。轮子向前时左侧原始计数为负、右侧为正，encoder_sign设为左-1、右-1。参数格式8迁移旧2/4/5/6/7/8时应用这组方向，已保存的车辆尺寸、增益和其他配置继续保留。停车执行para → save to flash保存迁移结果。

摄像头与队友视觉接口使用 `image[120][188]`，即120行、188列的灰度图。列号 `u=0..187`，行号 `v=0..119`，视觉直接用整帧坐标和原始八参计算地面位置。屏幕宽128像素，预览显示原图第30～157列。

V1.50.16 写入 Flash 参数格式7。加载格式6时，旧预览中心加30，例如63.5变为93.5。格式2、4、5的中心已经是整帧坐标。升级这四种旧格式时，八个相机系数统一采用本次确认的原值，保留其余已有车辆参数和增益。停车后执行一次 `para → save to flash` 即可保存。以后在格式7下编辑的标定会按保存值加载。 [标定记录](2026-11-19相机标定记录.md)

当前固件V1.50.16，2026-11-19更新。本文按当前分层工程说明开发顺序和验收方法。

## 先分清你现在从哪里开始

如果只是运行本仓库，不必把所有文件重新写一遍：先执行第3节电脑测试与编译，再按第4节完成实物标定。如果是学习“从空模板怎么写出来”，按下面的阶段顺序逐个实现。

默认固件不能发车是预期行为：实际轮径、轮端计数、机械方向和新视觉时序尚未填好。编译成功只说明源码能生成芯片程序。

### 每完成一阶段，都应该看到什么

| 阶段 | 主要文件/改动 | 完成标准 | 不通过先查 |
|---|---|---|---|
| 1. 电脑工程 | tools/build.py、tools/test_host.py | 脚本成功退出，出现当次BUILD PASS和测试PASS | 工具链路径、WCH版本、头文件目录 |
| 2. 上电零输出 | User/board/board_motor.c、board_config.h | 架空时上电不转，EN为0 | EN/PH次序、H3与CN5脚号、重复初始化 |
| 3. 看计数 | User/control/side_encoder.c | 手转一整圈得到可重复计数，前进方向为正 | A/B接线、编码器供电、符号、齿比 |
| 4. 测速与PI | User/config/control_tuning.h | 专用低速测试中测量速度逐步接近目标，不持续振荡 | 轮端计数、轮径、方向，之后再看P/I |
| 5. 看清一帧 | User/board/camera_frame.c | 静态二值图完整且稳定，处理期不被新图覆盖 | 排线、曝光、DVP暂停重启、图像方向 |
| 6. 视觉输出 | User/vision/vision_pipeline.c | 白线在右时lateral_m为正；黑图返回无效 | 图像镜像、种子选路、目标位置和有效性 |
| 7. 接电控 | User/control/path_control.c | 右目标给负omega，最终左侧目标比右侧大 | 方向符号、会话号、帧时间、限幅 |
| 8. 落地与元素 | User/config/vision_tuning.h、track_profile.h | 普通路稳定后，逐个验证十字、Y、环岛及两圈记录 | 先回放视觉选路，再查控制和轮胎滑移 |

第4阶段可架空车轮，使用control / run 30开环测试，或在测速标定完成后使用vofa速度闭环。run 30固定30%，不受比赛占空比上限裁剪；不要乱填标定位来跳过start检查。

每阶段先通过再继续。否则例如测速方向本来反了，靠加大PI参数只会把错误放大。

## 1. 从模板到当前工程

固定起点为 `mode-for-ch32v307vct@7673725bab177202212c43a409d778aab45c5fab`。保留WCH/逐飞库及启动，应用分为vision/control/board/integration/shared/config。先读[项目结构与参数](项目结构与主流程参数说明.md)，目录和函数均对应实际源码。

1. 在 `User/board/board_config.h` 按epro确定EN/PH/编码器映射，在 `board_motor.c` 封装电机硬件。EN先拉低再选PWM，主函数保持一次零输出初始化。
2. 在 `User/control/side_encoder.c` 做16位连续CNT差分，换算轮端速度与里程；不要每周期清CNT。用实测轮端一圈有效计数，不能默认PPR×4。
3. 在control下写速度PI、曲率前馈＋横向偏差PD和差速约束；先电脑边界测试，再低速架空验证方向、占空比和计数。
4. 在board下完成DVP单帧借用/归还，实际暂停接收和DMA，归还后重启并丢弃首帧，验证缓冲不会被处理期覆盖。
5. 在vision下实现Otsu、连通道路、外轮廓、截断区间、折点和候选路径，再接多帧元素状态、路线历史及目标几何。
6. 通过 `VisionOutput` 接control曲率前馈＋横向偏差PD，主循环发布MotionRequest，TIM6固定5ms执行运动规划、测速PI和PWM。
7. 将视觉和电控默认值分别放在 `User/config/vision_tuning.h` 与 `control_tuning.h`，由共享参数代码统一校验、序列化。
8. 接本地按键、静态诊断和双槽Flash保存；无效图像、超时、非有限数和错误会话不能被当成有效运行目标。

## 2. 两套算法独立开发

视觉入口 `vision_pipeline_step` 返回VisionOutput，提供米制偏差/前向距离/曲率、帧/会话、有效性、速度建议和停车标记。视觉侧不生成车体角速度，不写PWM。替换识别方法时维持该协议；诊断用VisionFeatures不传给电控。

电控入口 `control_path_step` 只消费VisionOutput，曲率前馈＋横向偏差PD输出车体角速度；`motion_plan_step` 换算左右目标并限幅，`speed_pi_step` 输出EN占空比。可以分别替换方向、规划或速度算法。保持停止传播、会话检查和陈旧帧保护。

识别参数改vision_tuning；曲率前馈＋横向偏差PD、两侧速度PI与运动限幅改control_tuning。实际几何/编码器数据改vehicle_calibration，现场路线改track_profile。有效Flash记录会覆盖编译默认值，调参后确认实际加载的是哪一组参数。

## 4. 上板顺序

1. 架空四轮，确认共地、线束脚号和上电EN=0；原理图对应见[硬件核对](hardware/引脚与驱动核对.md)。
2. 用五向上/下和中键选择control / image观看当前灰度图，检查完整帧、曝光、镜像、重启缺行；UART3 PB10/PB11、115200供VOFA四通道调试。
3. 手转两侧轮子，测轮端一圈计数及正负号；填轮径、轮距、轴距和计数。
4. 专用低占空比架空测试确认PH机械前进方向，再恢复正式入口；先P后I调轮速，逐侧观察速度、发热与齿轮啮合。
5. 测相机前移距离及近远采样行对应前向距离；确认中断/图像最坏耗时、栈余量、曲率前馈＋横向偏差PD符号与增益。
6. 依次验证直线、普通弯/直角弯、十字直行、分叉两支、环岛进入/一周/退出和后轴清出。
7. 填现场事件顺序和终点距离，验证两圈记录；完成全部条件后才设CAL_MASK、CAL_CAPTURE_VALIDATED和CAL_VISION_V2_VALIDATED。完整比赛还需CAL_FULL_RACE与有效现场路线。

默认实测值和视觉验证开关为0，上电主菜单、禁止巡线发车。五向上/下选择、中键点按确认，KEY1点按返回；start自动完成准备/发车握手，control / stop停止电机与采集。para / save to flash静止保存后恢复菜单，不自动重启。

VOFA的I0/I1/I2/I3依次发送左斜坡目标、左实测速、右斜坡目标、右实测速，单位m/s。每20ms发送4个float32小端数，后接00 00 80 7F，共20字节。反馈无效时实测通道为NaN。

当前编码器为MT6701CT-ACD：厂家1024PPR × 当前TIM TI2二倍频 × 车轮直连1:1 = 每轮2048计数。现有编码器驱动、5ms采样和速度PI均不改，速度换算为π×0.0337×周期计数/2048/周期秒数；方向已按实测设为左-1、右-1，VOFA用于速度闭环调参。型号依据和完整过程见[V1.50菜单说明](V1.50屏幕菜单与调试.md)。
