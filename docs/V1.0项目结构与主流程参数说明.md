# 项目结构、主流程、函数调度与参数说明

对应固件：V1.2；更新：2026-11-01。本文按当前源码说明，不要求读者再去旧版本说明中拼接目录和接口。

## 先用三句话理解整车

摄像头告诉程序“白线往哪里延伸”；视觉算法选出应该追的目标；电控让左右两侧轮子用不同速度跟过去。四只轮子不是四个独立执行器，同侧前后轮由齿轮联动，所以只控制左右两组速度。

第一次阅读先看第1节两条链路、第3节运行顺序和第4节“参数去哪里改”。不需要先背完整函数名，文末清单用于写代码时查找。

| 术语 | 在这台车上是什么意思 |
|---|---|
| 帧 | 摄像头拍到的一张灰度照片 |
| 二值化 / Otsu | 把灰度变成黑白；Otsu根据这张图自动选分界亮度 |
| 连通域 | 从车前方那条白线出发，能沿相邻白像素走到的区域 |
| 外轮廓 / 截断区间 | 白区域的外边界 / 白路与照片边缘相交的一整段 |
| 目标点 | 视觉选定要让车头追过去的图像位置 |
| PD / PI | 用“偏了多少、变化多快”修方向 / 用“速度差多少、长期差多少”调电机 |
| PWM占空比 | 每个快速开关周期中，电机使能为高的时间比例；不是实测电流 |
| 中断 / 主循环 | 定时或事件触发的小段工作 / 程序反复执行的日常工作 |
| 会话号 | 本次准备发车的身份号，防止上一次运行的目标混进来 |
| Flash参数 | 断电后仍保存的设置；可能覆盖重新编译时填的默认值 |

## 1. 先认识两条链路

参考车是四轮、左右各一个电机，同侧前后轮由齿轮联动。控制对象为左右两条侧速度。图像链路负责“看路、选路和目标几何”，电控链路负责“转向、两侧速度和PWM”。

```text
User/vision：灰度帧→Otsu→连通道路→外轮廓/截断/折点→候选路径→元素状态→目标几何
                      ↓ VisionOutput
User/control：方向PD→MotionRequest→5ms差速规划→左右速度PI→PWM
                      ↑ 编码器反馈
```

视觉输出方向角右为正，电控车体角速度左为正，所以方向PD有负号。右目标使左侧快、右侧慢。像素距离不是实际米数，当前未用于距离减速。画面方向角也不是准确车体转角。

## 3. 上电、主循环与5ms调度

`main` 先初始化144MHz时钟，调用 `motor_init_zero` 保证EN为0，再初始化UART3日志和应用。电机零输出初始化只调用一次。

`app_boot_init` 顺序：TIM7时基/按键 → `param_defaults` → 实测CAL宏覆盖 → 有效Flash参数覆盖 → 编码器 → 控制状态STATIC → TIM6每5ms → 相机初始化/就绪标志 → 屏幕。

每次 `app_main_poll`：读取控制快照；会话改变时清选路与PD历史；有新帧才调用 `vision_pipeline_step`，再调用 `control_path_step` 并发布MotionRequest；可选静态二值图显示后归还帧；处理按键和诊断。

`vision_pipeline_step` 内部：`vision_line_process`（含 `vision_boundary_process`）→ `track_element_step` → `vision_target_step`。它不调用电控PD。`control_path_step` 只读取VisionOutput，不读图像、白段或边界。

TIM6每5ms：`board_clock_tick` → 实际dt/标定/相机检查 → `side_encoder_sample` → 读取运动请求并检查会话、可信度与拍摄时间 → 消费按键请求 → `run_manager_step` → `motion_plan_step` → 左右各一次 `speed_pi_step` → 电机输出 → 发布快照。

DVP帧完成回调冻结接收和DMA，发布帧号及完成时间。主循环借用期间保持缓冲稳定；归还后重新采集并丢弃重启首帧。帧时序仍需硬件验证。

主循环与中断通过短临界区复制结构。运行中不擦Flash、不接受远程改参，也不打印周期日志。主循环软件停止依赖轮询正常工作，不能作为独立硬件急停。

### 3.1 跨链路协议

`User/shared/vision_control.h::VisionOutput`：

| 字段 | 单位/作用 |
|---|---|
| `direction_rad` | 画面目标方向，右为正，rad |
| `distance_px` | 参考点到目标的像素距离，px |
| `speed_cap_mps` | 视觉按路况选择的建议车速上限，电控再限幅 |
| `state` | 道路元素状态 |
| `confidence`、`valid` | 可信度和有效性 |
| `stop_requested` | 请求停车，无效观察也保留此标记 |
| `reset_derivative` | 目标切换，通知PD重置D历史 |
| `frame_id`、`capture_ms`、`session_id` | 帧、拍摄时间和启动会话，避免重复/陈旧数据 |

方向PD在电控内生成 `MotionRequest::omega_raw`。电控拒绝重复帧、错误会话、非法数值、非正像素距离和负速度。共享AppParam是兼容Flash的公共配置格式，不代表两个模块可以互调内部算法。

### 3.2 状态与按键

| 状态/操作 | 行为 |
|---|---|
| STATIC_DEBUG | PWM0；可手动观察图像和轮子计数 |
| 中键 | 完成全部标定、相机就绪且两侧静止后进入READY |
| READY + KEY1 | 当前会话有新鲜有效图像后RUNNING |
| RUNNING + KEY2或元素停车 | STOPPING，目标降至零后回STATIC |
| FAULT + KEY2 | 清故障，重新准备 |
| STATIC + 右键 | 文字/当前Otsu阈值二值图切换 |
| STATIC + 下键长按2秒 | 静止且参数合法时保存另一个Flash槽并复位 |

按键消抖40ms；图像软超时150ms先减速，硬超时600ms故障回零。运行dt超过20ms故障；控制执行超过4ms累计三次故障。没有IMU、硬件看门狗或可读驱动电流/故障反馈。

## 4. 参数：分开改，统一校验和保存

| 位置 | 应该修改的内容 |
|---|---|
| `User/config/vision_tuning.h` | 图像中心、参考线宽、行跳变、确认/释放、清出和环岛门槛 |
| `User/config/control_tuning.h` | 方向PD、轮速PI/前馈、编码器滤波、车速/占空比/加减速和超时 |
| `User/config/vehicle_calibration.h` | 轮径、轮距、轴距、轮端计数、行距及标定开关 |
| `User/config/track_profile.h` | 一圈元素顺序、环岛选支和终点距离 |
| `User/board/board_config.h` | 引脚与前进电气极性 |
| `User/shared/vehicle_param.c` | 参数校验/编码，不再集中存放两组调参默认值 |

`param_defaults` 清零后分别调用vision/control默认值函数，之后加载CAL和有效Flash记录。Flash有效记录会覆盖编译默认值；改变调参文件后仍读旧值时，先处理旧参数槽再烧录。字段 `visual_kp/kd/tau` 是电控方向PD的兼容名称，调参归control文件。

### 4.1 实测与发车条件

| 宏/字段 | 意义和填写方法 |
|---|---|
| `CAL_WHEEL_LEFT_M/RIGHT_M` → `wheel_left/right_m` | 两侧负载下有效轮径；默认 0，必须实测 |
| `CAL_TRACK_M` → `track_m` | 左右轮中心距；默认 0 |
| `CAL_AXLE_M` → `axle_m` | 前后轴中心距；默认 0 |
| `CAL_COUNTS_LEFT/RIGHT` → `counts_left/right` | 每侧轮端一圈有效计数；默认 0 |
| `CAL_ROW_NEAR_M/FAR_M` | 静止地面上近端/远端采样行对应前向距离；必须远大于近 |
| `CAL_CAMERA_FORWARD_M` | 相机相对车体轴间中心的前移距离 |
| `CAL_MASK` | 位0几何、位1编码器、位2方向、位3图像、位4时序；全部验证才为31 |
| `CAL_CAPTURE_VALIDATED` | 实测帧暂停/重启可靠后设1；不是相机初始化成功就设1 |
| `CAL_VISION_V2_VALIDATED` | 新视觉的方向、最坏处理时间、场地效果验证后设1；旧Flash不能绕过该编译期条件 |
| `CAL_FULL_RACE` | 0 普通训练；1 正式路线模式，需要完整现场事件配置 |
| `encoder_sign[2]` | 在 `User/config/control_tuning.h` 中设置各侧 +1/-1，统一轮子前进计数为正 |
| `effective_track_m` | 默认0，表示先用几何轮距；实测转向后填写等效值 |

数值校验还检查 NaN/无穷大、轮径/轮距范围、占空比/时间范围。不能只改掩码来绕过尺寸和计数为零的检查。完整比赛还要求 `APP_ROUTE_LENGTH>0` 和终点距离大于0。

### 4.2 速度闭环、方向与限幅

| 参数 | 默认值 | 直白说明 |
|---|---|---|
| `encoder_tau_s` | 0.025 | 测速滤波时间常数，过大反应慢 |
| `kp_left/right` | 0.2 / 0.2 | 侧速度 P，误差立即影响占空比 |
| `ki_left/right` | 0.4 / 0.4 | 侧速度 I，补长期偏差 |
| `ff_left/right` | 0 / 0 | 速度前馈，测出速度与占空比关系后再用 |
| `integral_limit` | 0.2 | 积分贡献绝对值上限 |
| `duty_limit` | 0.25 | 最高25% EN，占空比不是电流；校验上限0.8 |
| `speed_limit_mps` | 0.4 | 任一侧最高速度 |
| `accel_mps2/decel_mps2` | 0.3 / 0.6 | 目标增速/减速斜率 |
| `inner_ratio` | 0.15 | 内轮最低比例约束，减少零速附近急旋 |
| `visual_kp/kd` | 1.5 / 0.05 | 目标方向角P与变化率D，生成车体角速度，归电控侧 |
| `visual_tau_s` | 0.05 | D 项滤波时间常数 |
| `center_x_px` | 93.5 | 图像目标中心，依据装配与画面实测修正 |
| `speed_normal` | 0.2 | 普通目标车速上限 |
| `speed_corner` | 0.12 | 弯道速度上限 |
| `speed_element` | 0.1 | 十字、Y、环岛等状态速度上限 |

例如车速 0.2m/s、等效轮距0.14m、请求右转角速度 -1rad/s，未触发其他限幅时左右目标为0.27和0.13m/s。PI 各自追踪目标。轮子打滑时，实际转弯还会偏离这个计算值。

| 参数 | 默认值 | 用途 |
|---|---|---|

| `width_near_px/far_px` | 20 / 5 | 近远端白线宽度参考，用于分叉间距判据 |
| `row_jump_px` | 28 | 相邻采样行候选路径允许的位置变化 |
| `confirm_ms` | 80 | 持续证据多久才确认元素转移 |
| `release_ms` | 120 | 单线与清出稳定时间 |
| `clear_distance_m` | 0.12 | 后轴清出额外余量 |
| `island_min_distance_m` | 0.5 | 出环允许前至少走的轮周距离，须按现场环岛标定 |
| `island_min_turn_rad` | 5.4 | 接入真实航向后才启用的累计转向门槛 |

### 4.4 现场事件序列与两圈

在 `User/config/track_profile.h` 配置**一圈内依次遇到的分叉元素**。0～7 代表不同 Y 的固定身份；128 代表环岛。十字由通用直行状态处理，不占这个序列。

```c
/* 只是格式示例，不是从考核图推断出的现场路线。 */
#define APP_ROUTE_LENGTH 3u
#define APP_ROUTE_SEQUENCE {0u, 128u, 1u}
#define APP_ISLAND_ENTER_BRANCH 0u
#define APP_FINISH_DISTANCE_M 0.6f
```

示例表示一圈 Y0、环岛、Y1，第二圈重复。事件只有后轴清出才计数；每个 Y 用 `passed_mask` 记录左/右。累计走完两圈事件后，要求所有 Y 的 mask 为3，再按实测终点距离请求停止。终点距离从最后元素后轴清出的时刻起算。

事件顺序若不对或视觉误把额外岔路当元素，就可能选错身份；本版没有自动地图定位。必须逐元素验证，不能直接照用示例。相邻两圈的最后元素至第一个元素应能由普通循迹连续连接；若终点距离途中还有额外分叉，当前路线表示要扩展。

### 4.5 内存、持久化与编译选项

图像容量188×120=22560字节；只保留一张灰度图，另有2820字节连通域位图和512字节分时复用的Otsu/种子缓冲。每行4白段、最多4路径；容量溢出拒绝作为有效视觉请求。固定数组无动态图像分配。

链接允许248KiB Flash、32KiB RAM，栈固定2KiB。Flash 的物理地址 `0x0803E000` 与 `0x0803F000` 各预留4KiB。当前固件在别名地址0链接，由 WCH 下载工具映射到芯片 Flash；参数操作使用0x080…物理地址。不要选择会覆盖参数保留区的旧链接脚本。

参数每条256字节，明确序列化 float32，含版本、序号、CRC32，最后4字节提交标记最后写。启动选有效且更新的一槽。写失败仍保留另一槽；这不能替代供电和掉电实测。保存后立即复位，避免擦写暂停影响时基。

当前没有启用 IMU、硬件看门狗或驱动故障反馈。`APP_ENABLE_TFT`、`APP_ENABLE_PARAM_FLASH` 是预留宏，V1.2 尚未据其裁剪驱动，若需去屏或去 Flash 请修改实际调用后重新验证。


## 5. 验证结果和实际边界

当前目标构建：Flash63700字节；RAM静态数据加预留2KiB栈合计30908字节。链接预算248KiB Flash、32KiB RAM。构建报告保留第三方原有警告；新应用严格警告检查通过。

电脑回归：默认路线138420断言，测试路线138424断言；视觉独立链接测试和电控独立链接测试通过。计数器遍历贡献大量断言，不等于硬件测试覆盖率。具体记录见 `release/v1.2/build-report.json` 和 `test-report.json`。

视觉当前追踪一条外轮廓，尚未枚举所有环岛内部孔洞；折点左右是画面半区标记，普通弯道使用近折点目标修正。环岛拓扑和完整一周判定需现场验证。原始算法案例、编译成功都不代表已烧录或实车跑通。

构建和上板顺序见[代码书写流程](代码书写流程.md)，算法原理见[电控算法文档](智能车电控算法开发文档.md)，替换模块见[V1.2分层说明](V1.2视觉电控分层与调参.md)。
